# Абонементи

Спецификация задачи бэкенда. Решения согласованы с заказчиком 2026-11-11 по видео Altegio
(«Типи абонементів», см. `frontend-loyalty-page.md`, раздел 1.4). Кода здесь нет — только постановка.
Опирается на `certificates.md` (продажа строкой чека, выпуск в `payments.settle`, снимок шаблона),
`loyalty-accounts.md` (журнал, блокировки, идемпотентность) и бонусные услуги карты
(`RecordService.is_bonus`, `loyalty_bonus_progress` / `loyalty_bonus_operations`).

Не входят: онлайн-продажа (платёжной системы нет), уведомления клиенту, перенос абонементов
из Altegio (отдельная задача), продление и докупка единиц, возврат денег, количество в строке
услуги записи, фронтенд (отдельная задача после этой).

---

## 1. Согласованные решения

| # | Решение |
|---|---|
| 1 | Единица абонемента задаётся в типе: **посещения** (строка услуги в визите = 1) или **минуты** (строка услуги списывает свою длительность `RecordService.duration_minutes`). Пример: абонемент «Солярій 15 хв», клиент записан на услугу «Солярій 3 хв» — списывается 3, остаётся 12. Количества в строке записи нет и не добавляем: длительность берётся из услуги (*уточнено 2026-11-11*) |
| 2 | Баланс **общий** (N единиц на любую услугу из списка) или **раздельный** (своё N на каждую услугу) — задаётся в типе |
| 3 | Срок — N дней или месяцев; **0 — бессрочный** |
| 4 | Активация — при продаже или при первом визите; для «при первом визите» можно задать автоактивацию через N дней после продажи |
| 5 | Заморозка — **один раз** за жизнь абонемента; лимит дней в типе — **суммарный** на весь абонемент (0 — без лимита). Замораживают администратор и суперюзер |
| 6 | Абонемент действует **во всех салонах сети**. Выручка — у салона-продавца, взаиморасчётов нет |
| 7 | Абонемент **именной**: продаётся клиенту чека, передать или подарить нельзя. Кодов нет |
| 8 | Покупку абонемента можно оплатить любым способом: кассой, особовим рахунком, кешбэком, сертификатом (в пределах правил этих способов). На строку-абонемент **действуют скидки** карты и личная скидка, на неё **начисляется кешбэк** |
| 9 | **Возврата денег нет.** По истечении срока остаток **сгорает** |
| 10 | Стоимость услуги, оплаченной абонементом, в отчётах — **пересчёт на единицу**: оплаченная сумма строки-абонемента / число единиц. Флага в типе нет — пересчёт всегда |
| 11 | **Мастер процент за услугу по абонементу не получает** |
| 12 | Списание — **вручную**: в окне оплаты администратор выбирает абонемент для строки услуги, если у клиента есть подходящий. Автоматически не списывается |
| 13 | Продления срока и докупки единиц нет. Нужно больше — новый абонемент |
| 14 | Типы абонементов создаёт **только суперюзер**, один раз на сеть. Продают и списывают администраторы всех салонов |
| 15 | Клиент видит свои абонементы (остаток, срок, статус) в Telegram-боте — только просмотр |

## 2. Термины

- **Тип абонемента** — шаблон в каталоге сети: услуги, баланс, цена, срок, правила активации и заморозки.
- **Абонемент** — экземпляр, проданный клиенту: снимок типа на момент продажи, остатки, сроки, статус.
- **Единица** — посещение (одна строка услуги в визите) или минута (длительность строки услуги) — по `unit_kind` типа.
- **Списываемое количество строки** — 1 для посещений, `RecordService.duration_minutes` для минут.
- **Списание** — строка услуги визита оплачена абонементом: в итог визита 0 ₴, остаток уменьшается на списываемое количество.
- **Стоимость единицы** (`unit_value`) — оплаченная сумма строки-абонемента / всего единиц (решение 10).

Статусы:

```
pending (продан, ждёт первого визита)
   │ первое списание / автоактивация через N дней
   ▼
active ──заморозка──► frozen ──разморозка (вручную или по лимиту)──► active
   │
   ▼
spent (остаток 0) / expired (срок вышел, остаток сгорел) / cancelled (чек покупки отменён)
```

При `activation_mode = on_sale` абонемент сразу `active`.

## 3. Данные

### 3.1. Master DB (абонемент общий для сети — решение 6)

**`subscription_types`**
- `name`, `price` (> 0), `unit_kind` (`visits` | `minutes`), `balance_mode` (`shared` | `separate`), `total_units` (обязателен при `shared`, NULL при `separate`);
- `duration_value` (≥ 0; 0 — бессрочный), `duration_unit` (`day` | `month`);
- `activation_mode` (`on_sale` | `first_visit`), `auto_activate_days` (NULL — нет; только при `first_visit`);
- `freeze_allowed`, `freeze_max_days` (0 — без лимита);
- `is_active` (архив = false), `sort_order`, `created_at`, `updated_at`.

**`subscription_type_services`** — `(type_id, salon_id, service_id, units)`; `units` обязателен при
`separate`, NULL при `shared`. Пары (салон, услуга), без FK на шард, EXISTS-проверка в шарде при
сохранении — как `certificate_template_services`. Хотя бы одна услуга.

**`subscriptions`**
- `client_id` (NOT NULL — решение 7), `type_id`;
- снимок: `name`, `unit_kind`, `balance_mode`, `total_units`, `duration_value`, `duration_unit`, `activation_mode`,
  `auto_activate_days`, `freeze_allowed`, `freeze_max_days`;
- `paid_amount` (оплачено за строку после скидок), `unit_value` (= `paid_amount` / всего единиц,
  `Numeric(12, 4)` — для минут копейки на единицу теряются; всего единиц = `total_units` или сумма `units` при `separate`);
- продажа: `sold_salon_id`, `sold_receipt_id`, `sold_at`;
- `status`, `activated_at`, `expires_at` (NULL — бессрочный или ещё не активирован),
  `auto_activate_at` (NULL — нет);
- заморозка: `frozen_at`, `freeze_until` (NULL — без лимита), `unfrozen_at`, `frozen_days`
  (фактически), `freeze_used` (bool).

**`subscription_services`** — снимок услуг: `(subscription_id, salon_id, service_id, units)`.

**`subscription_balances`** — текущий остаток по «корзине»: при `shared` одна строка с
`service_key = NULL`, при `separate` по строке на пару (салон, услуга). Меняется **только**
вместе с записью в журнале — как `loyalty_bonus_progress`.

**`subscription_operations`** — неизменяемый журнал:
`subscription_id`, `balance_id`, `type` (`issue` | `use` | `reversal` | `expire` | `cancel`),
`delta` (единицы), `balance_after`, `salon_id`, `receipt_id`, `record_id`, `record_service_id`,
`author`, `reverses_id`, `idempotency_key` (unique), `created_at`.
Заморозка/разморозка остаток не меняют — пишутся в аудит, не в журнал.

### 3.2. Shard DB салона

- **`receipt_subscription_lines`** — по образцу `receipt_certificate_lines`: `receipt_id`, `type_id`,
  `name`, `amount` (цена), `paid_amount` (после скидки), `subscription_id` (после выпуска, unique).
  Одна строка — один абонемент.
- **`record_services`**: новые поля `subscription_id`, `subscription_units`, `subscription_unit_value` (все NULL).
  Списываемое количество фиксируется при оплате: правка длительности услуги в каталоге после
  оплаты на списание не влияет.
  Строка, оплаченная абонементом, идёт в итог визита как 0 ₴ — по образцу `is_bonus`.
  `subscription_unit_value` — стоимость услуги для отчётов (решение 10).
- Категория операций `subscriptions` («Продаж абонементів») — по образцу `certificates`.

## 4. Типы абонементов (суперюзер)

API по образцу шаблонов сертификатов:
- `GET /subscriptions/types?active=` — список; в ответе `issuedCount` (сколько продано, кроме `cancelled`);
- `GET /subscriptions/types/{id}`, `POST /subscriptions/types`, `PATCH /subscriptions/types/{id}`.

Валидация:
- `shared` → `total_units ≥ 1`, у услуг нет `units`; `separate` → у каждой услуги `units ≥ 1`;
- пары (салон, услуга) уникальны, салоны из сети, услуги существуют в шарде;
- `auto_activate_days` только при `first_visit`; `freeze_max_days` только при `freeze_allowed`.

Правка типа на проданные абонементы не влияет (снимок). Удаления нет — только архив
(`is_active = false`): архивный тип нельзя продать, проданные работают. Аудит изменений — как у шаблонов сертификатов.

## 5. Продажа

Где: окно оплаты визита и продажа без записи — «+ Абонемент», выбор активного типа.

1. В чеке обязателен клиент (решение 7). Нет клиента — 422.
2. Строка-абонемент участвует в «Продано», в скидке и в кешбэке **как обычная строка** (решение 8):
   `checkout.py` получает вид строки `subscription`, скидка карты и личная скидка применяются,
   `paid_amount` строки — после скидки.
3. Оплатить строку можно любым способом. Ограничения самих способов действуют: сертификат
   `scope = services` строку-абонемент не покрывает (это не услуга).
4. Выручка — `income` в кассу салона-продавца с категорией `subscriptions` за кассовую часть, как у
   сертификатов (деление кассовой части на операции по категориям — тот же механизм).
5. Выпуск — в `payments.settle` в транзакции Master, вместе со списаниями:
   ключ `subs:{salon}:{receipt}:{line}`. Создаются абонемент, снимок услуг, балансы и операции `issue`.
   При `on_sale` — `status = active`, `activated_at = sold_at`, `expires_at` по сроку.
   При `first_visit` — `pending`, `auto_activate_at = sold_at + auto_activate_days`.
   Если чек в шарде упал — компенсация как у сертификатов; ночная сверка аннулирует сироты.
6. **Отмена чека покупки** — только если по абонементу не было ни одного `use` (с учётом сторно).
   Абонемент → `cancelled`, операция `cancel` в ноль. Иначе 409 «Абонементом вже користувалися».

## 6. Списание на визите

1. `GET /clients/{id}/subscriptions?usable_for_salon={salon}` — абонементы клиента со статусом
   `pending` / `active` и остатком > 0, с услугами и остатками; фронт по нему показывает выбор
   у подходящих строк (решение 12).
2. В запросе оплаты для строки услуги передаётся `subscription_id`. Проверки:
   - абонемент клиента этого визита;
   - статус `pending` или `active` (не `frozen`, не истёк: `expires_at` > сейчас);
   - пара (салон визита, `service_id` строки) есть в снимке;
   - остаток корзины ≥ списываемого количества строки. Не хватает (осталось 2 минуты, услуга
     на 3) — 422 «Недостатньо залишку абонемента»; частичного списания с доплатой нет;
   - одна строка — один абонемент; несколько строк могут списывать с одного абонемента.
3. Списание — в `payments.charge`, ключ `pay:{salon}:{receipt}:subs:{record_service_id}`,
   операция `use`, `delta = −количество` (1 или `duration_minutes` строки). В строке `subscription_id`,
   `subscription_units` (списано), `subscription_unit_value = round(unit_value × списано, 2)`,
   строка в итоге 0 ₴. Скидка и кешбэк на неё не действуют (она 0 ₴).
4. Первое списание `pending`-абонемента активирует его: `activated_at = now`, `expires_at` по сроку.
5. Остаток 0 по всем корзинам → `spent`.
6. Порядок блокировок в Master: денежный счёт → кешбэк → сертификаты → **абонементы (по id)** →
   прогресс бонусов.
7. **Отмена оплаты / чека визита** — `reverse_payments`: операция `reversal` (+списанное), строка снова по
   цене, `spent` → `active`. Если абонемент уже `expired` — сторно делаем (единица возвращается
   в журнал), но статус остаётся `expired`, остаток сразу сгорает повторной операцией `expire`.
   Активацию отмена первого списания **не откатывает**.
8. Ночная сверка: операции `use` без чека в шарде — сторнируются, как у остальных списаний.

## 7. Заморозка (решение 5)

- `POST /subscriptions/{id}/freeze` — администратор или суперюзер. Можно, если `freeze_allowed`,
  `freeze_used = false`, статус `active`, срок не бессрочный (бессрочный замораживать незачем).
  Ставит `frozen`, `frozen_at = now`, `freeze_used = true`,
  `freeze_until = now + freeze_max_days` (NULL при лимите 0).
- `POST /subscriptions/{id}/unfreeze` — вручную в любой момент. `frozen_days` = фактические дни
  (неполный день — вверх), `expires_at += frozen_days`, статус `active`.
- По `freeze_until` размораживается фоновой задачей теми же правилами.
- Повторно заморозить нельзя, даже если лимит не выбран полностью.
- Обе операции — в аудит с автором.

---

## 8. Фоновые задачи (Celery beat, ежечасно, идемпотентно)

1. **Автоактивация:** `pending` с `auto_activate_at ≤ now` → `active`, `activated_at = auto_activate_at`.
2. **Авторазморозка:** `frozen` с `freeze_until ≤ now` → как ручная разморозка.
3. **Истечение:** `active` с `expires_at ≤ now` → `expired`, по каждой корзине с остатком > 0 —
   операция `expire` в ноль (ключ `expire:{subscription}:{balance}`).
   `pending` не истекает, пока не активирован (автоактивация запустит срок).

## 9. Чтение

- `GET /clients/{id}/subscriptions` — все абонементы клиента (для карточки клиента): статус, услуги
  с остатками, срок, заморозка, где и когда куплен.
- `GET /subscriptions/{id}/operations` — журнал.
- `GET /subscriptions?status=&type_id=&salon_id=&q=&page=` — реестр проданных (для «Лояльність»,
  как реестр сертификатов), суперюзер.
- Бот (решение 15): в разделе клиента — активные/ожидающие/замороженные абонементы: название,
  остатки по услугам, «діє до», статус. Только просмотр.

## 10. Отчёты и зарплата

- Выручка признаётся при продаже, у салона-продавца. Визит по абонементу денег и выручки не создаёт.
- Отчёты по услугам / мастерам считают строку, оплаченную абонементом, по
  `subscription_unit_value` (решение 10) — отдельной колонкой/признаком, чтобы не смешивать с
  деньгами кассы.
- Начисления мастеру сейчас в системе не считаются (`commission_percent` только хранится).
  Требование на будущее: строки с `subscription_id` в базу процента мастера **не входят** (решение 11).

## 11. Права

| Действие | Кто |
|---|---|
| Типы абонементов, реестр проданных | суперюзер |
| Продажа, списание, заморозка/разморозка | администратор, суперюзер |
| Просмотр абонементов клиента | администратор, суперюзер; мастер — нет |

## 12. Тесты (минимум)

- тип: валидация `shared`/`separate`, услуги чужого салона, архив не продаётся;
- продажа: без клиента — 422; скидка карты и кешбэк на строку; `unit_value` от суммы после скидки;
  выпуск идемпотентен; компенсация при падении чека; отмена чека до и после использования;
- списание в минутах: 15 − услуга 3 мин = 12; не хватает остатка — 422; сторно возвращает минуты;
- списание: чужой клиент, `frozen`, истёкший, услуга не из списка, остаток 0, `shared` и `separate`,
  активация `pending` первым визитом, `spent` и возврат в `active` при сторно, сторно после истечения;
- заморозка: один раз, лимит, продление `expires_at` на фактические дни, авторазморозка;
- фоновые задачи: автоактивация, истечение со сгоранием, повторный запуск ничего не дублирует;
- конкурентное списание последней единицы двумя чеками — одно проходит.
