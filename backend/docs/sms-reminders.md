# SMS-нагадування про візит

Спецификация задачи. Решения согласованы с заказчиком 2026-11-03. Кода здесь нет — только постановка.
Расширяет существующее Telegram-напоминание (`workers/tasks/reminders.py`, `workers/tasks/notify.py`).

Не входят: маркетинговые и массовые рассылки, Viber, двусторонние SMS (ответ клиента), SMS
мастерам и администраторам, другие страны, редактирование текста салоном, лимиты бюджета.

---

## 1. Согласованные решения

| # | Решение |
|---|---|
| 1 | Только **Украина**. Номера вне `+380` не получают SMS |
| 2 | Провайдер — **местный агрегатор**, основной кандидат **TurboSMS** (~1–1.3 ₴/SMS против ~7 ₴ у Twilio). Код работает через свой интерфейс провайдера, конкретный агрегатор — подключаемая реализация |
| 3 | Альфа-имя отправителя — **`ADELANTE`**, одно на всю сеть |
| 4 | Напоминание по умолчанию **за 30 минут**; время **задаёт каждый салон у себя** в «Налаштування» |
| 5 | Канал по умолчанию: **Telegram, если клиент подключил бота, иначе SMS**. Канал можно переключить |
| 6 | Канал переключает **клиент в боте**, а в CRM — **администратор и суперюзер** (в карточке клиента) |
| 7 | Клиент может **отказаться от напоминаний** совсем (отдельно от флага `reminder_enabled` записи) |
| 8 | Если Telegram не доставил (бот заблокирован, чат не найден) — **сразу отправляем SMS** |
| 9 | Запись, созданная позже момента напоминания (меньше чем за N минут до начала), напоминание **не получает** — как сейчас |
| 10 | Нужен **журнал отправок** и **отчёт по SMS и их стоимости по салонам** |
| 11 | Текст SMS **фиксированный** на всю сеть, украинский, **≤ 70 символов** (одно SMS в кодировке UCS-2) |

Бизнес-часть (вне разработки, делает владелец): договор с провайдером на ФОП/ТОВ, регистрация
альфа-имени `ADELANTE` у операторов (несколько дней), способ пополнения баланса. Разработка от
этого не зависит — до подключения всё работает на провайдере `console`.

## 2. Термины

- **Напоминание** — одно событие `record.reminder` на запись. Доставляется **одним** каналом
  (плюс SMS как запасной, если Telegram не доставил).
- **Канал** — `telegram` или `sms`.
- **Предпочтение клиента** (`reminder_channel`) — `auto` | `telegram` | `sms` | `none`.
- **Отправка** (delivery) — одна попытка доставки напоминания в конкретный канал; строка журнала.
- **Сегмент** — одна SMS-часть. Кириллица → UCS-2: 70 символов в одном сегменте, 67 в каждой части
  длинного сообщения. Провайдер берёт деньги за сегмент.

---

## 3. Выбор канала

Предпочтение хранится у клиента (Master DB — клиент общий для сети):

| `reminder_channel` | Есть `telegram_user_id` | Нет `telegram_user_id` |
|---|---|---|
| `auto` (по умолчанию) | Telegram, при неудаче → SMS | SMS |
| `telegram` | Telegram, при неудаче → SMS | SMS (Telegram невозможен) |
| `sms` | SMS | SMS |
| `none` | не отправляем | не отправляем |

- `telegram` без привязанного бота ведёт себя как `auto` — клиент не должен остаться без
  напоминания из-за отвязки бота. Иначе `auto` и `telegram` совпадают; `telegram` нужен, чтобы
  явный выбор клиента сохранялся и отображался.
- **Неудача Telegram** = постоянная ошибка 4xx (бот заблокирован, чат не найден, пользователь
  удалён). Временные (сеть, 429, 5xx) — повторы, как сейчас; если повторы исчерпаны — тоже SMS.
  Сейчас `workers/telegram.py::send_message` на 4xx только пишет предупреждение и ничего не
  возвращает — нужно, чтобы вызывающий узнавал результат (возвращаемое значение или исключение
  «постоянная ошибка»), остальные вызовы `send_message` при этом не ломаются.
- Нет телефона, номер не украинский или некорректный → SMS не отправляется, в журнале строка со
  статусом `skipped` и причиной.
- Флаг записи `reminder_enabled = false` по-прежнему отключает напоминание по этой записи.

---

## 4. Время напоминания

- Настройка салона `reminder_lead_minutes`, по умолчанию **30**, допустимо **15…1440** (до суток).
  Хранится в таблице `settings` шарда (как `salon_info`, `app/services/salon_settings.py`), новый
  ключ, например `notifications`. Миграция не нужна.
- Сканер уже обходит салоны по отдельности (`scan_shard`) — он читает настройку своего салона
  вместо константы `REMINDER_LEAD`. Окно с перекрытием (`WINDOW_MARGIN`) и `reminder_sent_at` —
  без изменений.
- Изменение настройки действует на ещё не отправленные напоминания. Если новое время больше
  старого и момент напоминания для записи уже прошёл — по этой записи напоминания не будет
  (как решение 9).
- Telegram-текст сейчас пишет «Через 30 хвилин» — заменить на фактическое время визита
  («Сьогодні о 14:30» / «Завтра о 10:00»), чтобы не зависеть от настройки.

## 5. Текст SMS

Фиксированный шаблон, время — локальное время салона (`Europe/Kyiv`):

```
Нагадуємо: {день} о {HH:MM}, {салон}. Чекаємо!
```

- `{день}` — `сьогодні` / `завтра` / `DD.MM`.
- `{салон}` — название салона (`Salon.name`).
- Пример: `Нагадуємо: сьогодні о 14:30, Adelante Позняки. Чекаємо!` — 55 символов (на название салона остаётся 31 символ).
- Если текст длиннее 70 символов — укорачиваем название салона с `…`; если и так не влезает —
  убираем `, {салон}`. Итог **всегда ≤ 70 символов** — это проверяется тестом.
- Альфа-имя `ADELANTE` уже видно как отправитель — в текст его не дублируем.
- Ссылок в SMS нет (длина и фильтры операторов).

## 6. Провайдер

Интерфейс (модуль, например, `app/notifications/sms/`):

- `send(phone_e164, text, reference) -> SendResult` — `provider_message_id`, число сегментов,
  стоимость (если провайдер её вернул), либо ошибка: **временная** (повторять) или **постоянная**
  (неверный номер, отклонено — не повторять).
- `parse_status(...)` / `fetch_status(...)` — статус доставки (см. 7.2).

Реализации:

| Имя | Назначение |
|---|---|
| `console` | По умолчанию в dev и тестах: пишет в лог, возвращает успешный результат |
| `turbosms` | Боевой. HTTP API TurboSMS, авторизация токеном. Перед реализацией **сверить с официальной документацией** TurboSMS: метод отправки, формат ответа, статусы, вебхук DLR, коды ошибок |

Конфиг (`app/config.py`, переменные окружения): `SMS_PROVIDER` (`console` | `turbosms`),
`SMS_SENDER` (= `ADELANTE`), `TURBOSMS_TOKEN`, `SMS_PRICE_UAH` (цена сегмента для отчёта,
если провайдер стоимость не возвращает), секрет вебхука. Токены не должны попадать в логи
(как сделано для Telegram в `workers/telegram.py`).

Номер — через `app/services/phones.py::normalize_phone`, отправляем только `380XXXXXXXXX`
(12 цифр). `Client.additional_phone` не используем.

## 7. Отправка и журнал

### 7.1. Поток

1. `scan_shard` (как сейчас) помечает `reminder_sent_at` и после commit ставит задачу
   доставки с конвертом `record.reminder`. В payload добавить то, что нужно для SMS и выбора
   канала, либо дочитывать в задаче — на усмотрение реализации.
2. Задача доставки (очередь `notifications`) по таблице раздела 3 выбирает канал.
3. Telegram: дедуп `sent:{event_id}:client_tg` (как сейчас). Постоянная ошибка → шаг 4.
4. SMS: дедуп по `(event_id, sms)` в Redis **и** уникальность в журнале (одно SMS на
   напоминание даже при повторном прогоне). Временная ошибка → повтор с backoff; постоянная →
   статус `failed`, без повторов.
5. Каждая попытка в канал — строка журнала.

### 7.2. Журнал отправок — Shard DB салона

Новая таблица, например `reminder_deliveries`:

- `id`, `record_id`, `client_id`, `event_id`;
- `channel` (`telegram` | `sms`), `is_fallback` (SMS после неудачи Telegram);
- `phone` (нормализованный, для SMS), `text` (для SMS);
- `status`: `queued` → `sent` → `delivered` | `undelivered`; `failed` (ошибка отправки),
  `skipped` (не отправляли: нет/неверный номер, причина в `error`);
- `provider`, `provider_message_id`, `segments`, `cost` (₴, Numeric), `error`;
- `created_at`, `updated_at`.
- Уникальность `(event_id, channel)`.

Статусы доставки SMS: вебхук провайдера (публичный эндпоинт с секретом, ищет строку по
`provider_message_id` → нужен способ найти салон: например, `reference`/салон в callback-URL)
**или** периодический опрос статусов для строк `sent` младше суток — выбрать по документации
TurboSMS. Строки без финального статуса через сутки остаются `sent`.

## 8. Права

| Действие | Майстер | Адміністратор | Суперюзер |
|---|---|---|---|
| Видеть и менять канал напоминаний клиента (карточка клиента) | ❌ | ✅ | ✅ |
| Видеть историю напоминаний клиента (карточка) | ❌ | ✅ | ✅ |
| Менять `reminder_lead_minutes` своего салона (Налаштування) | ❌ | ✅ | ✅ |
| Отчёт по SMS и стоимости | ❌ | ❌ | ✅ (деньги — как Фінанси) |
| Клиент в боте: свой канал | — | — | — |

Изменения канала клиента и настройки салона — в журнал изменений (как остальные правки клиента и
настроек салона). Изменение клиентом в боте — с автором «клієнт (бот)».

## 9. API (ориентир, имена уточнить при реализации)

- Клиент: `reminder_channel` в ответе карточки клиента и в `PATCH` клиента.
- `GET /clients/{id}/reminders` — последние отправки клиенту в текущем салоне (дата, канал,
  статус, ошибка).
- `GET/PATCH /settings/notifications` — `reminder_lead_minutes`.
- `GET /reports/sms?from=&to=` (суперюзер) — по салонам: число SMS, сегментов, доставлено /
  не доставлено / ошибки / пропущено, стоимость; плюс сколько напоминаний ушло в Telegram.
  Данные из журналов шардов (fan-out по салонам, как в других сетевых отчётах — посмотреть, как
  сделано в существующих отчётах).
- Бот: получить и сменить канал клиента по `telegram_user_id` (рядом с
  `/bot/clients/by-telegram/{tg_user_id}/loyalty`).
- Вебхук статусов SMS (если выбран вебхук) — без авторизации пользователя, с секретом.

## 10. Интерфейс

**Web (`web/`)**
- Карточка клиента: поле «Нагадування» — `Автоматично (Telegram, якщо підключено)` / `Telegram` /
  `SMS` / `Не надсилати`; рядом — подключён ли бот. Блок истории напоминаний.
- Налаштування салону: «Нагадування клієнтам за N хвилин до візиту».
- Отчёт «SMS-нагадування» (суперюзер): период, таблица по салонам, итог по сети.

**Telegram-бот (`bot/tgbot`)**
- Команда/кнопка «Нагадування»: текущий выбор и inline-кнопки `Telegram` / `SMS` /
  `Не надсилати`. В боте `auto` показывается как Telegram.

## 11. Этапы

Каждый этап — отдельный коммит, отчёт и остановка до подтверждения.

1. **Провайдер и текст.** Интерфейс, `console`, `turbosms`, конфиг, сборка текста ≤ 70 символов,
   нормализация номера. Юнит-тесты (провайдер TurboSMS — на моках HTTP).
2. **Данные.** `Client.reminder_channel` (Master), журнал `reminder_deliveries` (Shard),
   настройка `reminder_lead_minutes`. Миграции, API настроек и поля клиента, журнал изменений.
3. **Доставка.** Время из настройки салона в сканере, выбор канала, SMS-задача, запасной SMS
   после неудачи Telegram, дедуп, запись в журнал, новый Telegram-текст.
4. **Статусы доставки.** Вебхук или опрос — по документации TurboSMS.
5. **CRM.** История в карточке клиента, отчёт по SMS (API + web), поле канала и настройка в web.
6. **Бот.** Выбор канала клиентом.
7. **Документация и проверка.** Обновить README/доки по переменным окружения; ручная проверка на
   реальном TurboSMS (10 бесплатных SMS) — после того как владелец даст токен.

## 12. Обязательные тесты

- Таблица выбора канала (раздел 3) — все строки, включая `telegram` без бота и `none`.
- Telegram 4xx → SMS ровно одно; Telegram 5xx/429 → повтор, не SMS; повторы исчерпаны → SMS.
- Повторный прогон задачи / сканера не даёт второго SMS (Redis и уникальность журнала).
- `reminder_lead_minutes`: сканер берёт значение салона; границы 15 и 1440; по умолчанию 30.
- Текст: всегда ≤ 70 символов, длинное название салона, `сьогодні` / `завтра` / дата, часовой пояс.
- Номера: разные форматы из `phones.py` → `380XXXXXXXXX`; неукраинский / пустой → `skipped`.
- Временная ошибка провайдера → повтор; постоянная → `failed` без повтора.
- Статусы доставки обновляют строку журнала; неизвестный `provider_message_id` не роняет обработку.
- Права: мастер не видит канал и историю; отчёт — только суперюзер.
- Бот меняет канал своего клиента и только его.

## 13. Открытые моменты

- Тихие часы: при `reminder_lead_minutes` в несколько часов SMS на утреннюю запись может уйти
  ночью. Сейчас не ограничиваем; вернуться, если салоны поставят большое значение.
- Тариф и цена сегмента — после договора; до этого `SMS_PRICE_UAH` из конфига.
- Если TurboSMS не подойдёт по договору — другой местный агрегатор (AlphaSMS, SMSClub, eSputnik)
  добавляется ещё одной реализацией провайдера.
