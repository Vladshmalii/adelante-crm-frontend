# Бриф для фронтенда: график работы по сменам

Бекенд готов (2026-09-29), ТЗ — `backend/docs/shifts.md`. Бекенд не менять. После
`npm run api:generate` всё ниже есть в `schema.gen.ts`.

Общее: префикс `/api/admin/v1`, заголовок `X-Salon-Id`, ответ `{data}`, camelCase. Даты
`YYYY-MM-DD`, время `HH:MM:SS` — по Киеву. Ошибки — `{message, code?, details?}`, `message` на
украинском (можно показывать как есть).

## Что изменилось в бекенде

1. **Рабочее время — смены по дням.** В ячейке «сотрудник × дата» — смена (с–по, необязательный
   перерыв) или отметка «Відпустка» / «Лікарняний»; пустая ячейка — выходной. Одинаково для
   мастеров и администраторов.
2. **Недельного графика и исключений больше нет:** удалены `GET/POST /staff/{id}/schedule` и
   `/staff/{id}/schedule/exceptions*`.
3. **Статусы сотрудника** — только `active` и `fired`. Значений `vacation`, `sick` в `StaffOut.status`
   и фильтре `GET /staff?status=` больше нет (отправка → `422`).
4. **Границы смен — часы работы салона** («Налаштування → Графік роботи»). Пока график салона не
   заполнен, смену поставить нельзя. При изменении часов салона будущие смены обрезаются (см. ниже).
5. **Запись вне смены** из Розкладу разрешена (админом мастеру, мастером себе), у записи признак
   `outsideShift`. В день відпустки або лікарняного мастера запись создать, перенести на этот день
   или назначить на неё мастера нельзя — `409`.
6. **Уведомления администраторам** (новая запись, перенос, отмена) получают только те, кто сейчас на
   смене, плюс суперюзеры всегда. Мастеру приходит сообщение, если его смены поменял кто-то другой.
7. **Сайт записи** — только внутри смен, окно записи 30 дней вперёд.

## Права

| | Смотреть сетку | Менять смены |
| --- | --- | --- |
| Суперюзер | всех | всех |
| Администратор | всех | свои и мастеров (не других администраторов) |
| Мастер | только себя | только свои |

В ответе сетки у каждой строки есть `canEdit` — по нему показывать или блокировать редактирование.

## 1. Сетка «Графік роботи»

`GET /shifts?dateFrom=&dateTo=` (даты включительно, не больше 62 дней):

```jsonc
{
  "salonScheduleConfigured": true, // false — показать «Спочатку заповніть графік роботи салону»
  "days": [
    // часы салона по датам — границы смен; null — салон закрыт
    { "date": "2026-10-05", "open": "08:00:00", "close": "20:00:00" },
    { "date": "2026-10-11", "open": null, "close": null }
  ],
  "staff": [
    // сначала мастера, потом администраторы (по имени); уволенных нет
    {
      "staffId": "…", "name": "Анна Коваль", "role": "master", "color": "#ff0000",
      "canEdit": true,
      "days": [
        {
          "date": "2026-10-05",
          "kind": "shift", // "shift" | "vacation" | "sick" | null (выходной)
          "start": "09:00:00", "end": "18:00:00",
          "breakStart": "13:00:00", "breakEnd": "14:00:00", // или null
          "comment": null,
          "recordsCount": 3 // записи мастера в этот день (кроме отменённых); у администраторов 0
        }
      ]
    }
  ]
}
```

Экран (по макету заказчика): горизонтальная сетка — слева имя и фамилия, вверху даты, в ячейке
«09:00–18:00» (с перерывом — подсказкой), «Відпустка», «Лікарняний» или пусто. Дни, когда салон
закрыт, — серым. Роль — подпись или разделитель между мастерами и администраторами.

## 2. Ячейка: поставить, изменить, убрать

По клику на ячейку — панель/модалка: смена или отметка + записи мастера на этот день.

- Записи в ячейке — существующий `GET /records?masterId=<id>&dateFrom=<дата>T00:00&dateTo=<дата+1>T00:00`
  (мастеру — только свои).
- `PUT /shifts/{staffId}/{date}` → обновлённая ячейка (формат как в `days`):

  ```jsonc
  { "kind": "shift", "start": "09:00", "end": "18:00", "breakStart": "13:00", "breakEnd": "14:00",
    "comment": "…" }
  // или отметка: { "kind": "vacation", "comment": "До 14.10" } — время игнорируется
  ```

- `DELETE /shifts/{staffId}/{date}` → `204` (день становится выходным).

Проверки бекенда (показывать `message`, для 409 — ещё список записей):

| Код | `code` | Когда |
| --- | --- | --- |
| `422` | `salon_not_configured` | График салона не заполнен (для смены; отметки можно) |
| `422` | `salon_closed` | Салон в этот день не работает |
| `422` | `outside_salon_hours` | Смена выходит за часы салона |
| `422` | `past` | Дата в прошлом (сегодня — можно) |
| `422` | — | Конец раньше начала, перерыв вне смены или указан наполовину (`details` по полям) |
| `409` | `has_records` | Удаление, замена отметкой или сокращение, при котором запись выпадет из смены; отметка на день с записями. `details.records = [{id, startAt, endAt, clientName}]` |
| `403` | — | Нет прав на этого сотрудника |

UI: в полях времени ограничить выбор часами салона (`days[].open/close`); прошлые дни — только
просмотр.

## 3. Массовое заполнение («Заповнити на період»)

`POST /shifts/fill` → отчёт `{created, updated, removed, skipped: [{staffId, date, reason, message}]}`.

```jsonc
{
  "staffIds": ["…", "…"],          // несколько сотрудников (с учётом прав, иначе 403)
  "dateFrom": "2026-10-01",         // с сегодня, не больше 62 дней
  "dateTo": "2026-10-31",
  "mode": "weekdays",               // weekdays | cycle | copy | mark
  "overwrite": false,               // false — только пустые дни; true — привести период к шаблону
                                    // (выходные шаблона очищают дни)
  // mode = weekdays: смена на день недели или null (выходной)
  "weekdays": {
    "monday": { "start": "09:00", "end": "18:00", "breakStart": "13:00", "breakEnd": "14:00" },
    "tuesday": null
    // … отсутствующий день = выходной
  },
  // mode = cycle: N рабочих / M выходных (2/2, 3/3, 5/2…), считая от startDate (по умолч. dateFrom)
  "cycle": { "workDays": 2, "offDays": 2, "startDate": "2026-10-01",
             "shift": { "start": "09:00", "end": "21:00" } },
  // mode = copy: повторить смены и отметки этих же сотрудников с другого периода (циклически)
  "copyFrom": { "dateFrom": "2026-09-22", "dateTo": "2026-09-28" },
  // mode = mark: відпустка / лікарняний на все дни периода
  "mark": { "kind": "vacation", "comment": "Відпустка" }
}
```

`skipped[].reason`: `exists` (уже заполнено, `overwrite = false`), `salon_closed`,
`outside_salon_hours`, `has_records` — показать отчёт пользователю («Пропущено 3 дні: …»).

## 4. Часы салона и смены

`PUT /settings/schedule` (вкладка «Графік роботи» в Налаштуваннях) теперь отвечает ещё полем:

```jsonc
"shifts": {
  "trimmed": 12,  // будущие смены подогнаны под новые часы
  "removed": 2,   // смены удалены (салон в этот день закрыт или ничего не осталось)
  "conflicts": [  // не изменены: на обрезаемое время есть записи
    { "staffId": "…", "staffName": "Анна Коваль", "date": "2026-10-06",
      "records": [{ "id": "…", "startAt": "…", "endAt": "…", "clientName": "…" }] }
  ]
}
```

После сохранения показать итог; при конфликтах — список со ссылками на записи («перенесіть записи
і поправте зміну»).

## 5. Розклад и записи

- `RecordOut.outsideShift: bool` — запись мастера не помещается в его смену (или смены нет).
  Выделять в сетке; при создании/переносе вне смены показать предупреждение «Запис поза зміною
  майстра» (запись всё равно создаётся).
- Слот вне смены в Розкладе кликабелен — администратор может поставить мастеру запись в нерабочее
  время (мастер — себе).
- День відпустки або лікарняного: `POST /records`, `PATCH /records/{id}` (время или мастер) →
  `409` «Майстер у відпустці 05.10.2026» / «…на лікарняному…».
- `GET /schedule` (колонки и нерабочее время Розкладу) считается по сменам; в `exception` — только
  отметки `vacation` / `sick`. Подробнее — [frontend-calendar.md](./frontend-calendar.md).

## 6. Реальное время

WebSocket-событие `shift.changed` — `payload: {staff_id, actor_id, changes: [{date, value}]}`:
обновить сетку (`GET /shifts`). Мастер получает только события своих смен.

## Что сделать во фронтенде (`web/`)

1. Страница «Графік роботи» (новый пункт меню для всех ролей): сетка из п. 1, редактирование ячейки
   из п. 2, «Заповнити на період» из п. 3.
2. Убрать редактор недельного графика и исключений в «Співробітники» (эндпоинтов больше нет);
   убрать статусы «У відпустці» / «На лікарняному» (вкладки, фильтры, подписи).
3. «Налаштування → Графік роботи»: показать отчёт `shifts` после сохранения (п. 4).
4. Розклад: `outsideShift`, предупреждение, запись в нерабочее время, ошибки 409 (п. 5).
5. Обновлять сетку по `shift.changed`.
