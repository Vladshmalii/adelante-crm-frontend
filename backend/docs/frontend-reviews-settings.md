# Бриф для фронтенда: Налаштування салону и отзывы

Бекенд готов (2026-09-29). Бекенд не менять. После `npm run api:generate` всё ниже есть в
`schema.gen.ts`.

Общее: префикс `/api/admin/v1`, заголовок `X-Salon-Id`, ответ `{data}`, camelCase. Время —
`HH:MM:SS` по Киеву. Тексты ошибок (`message`) на украинском.

## Что сделал бекенд

1. **Налаштування салону**: «Інформація про салон» и «Графік роботи салону» — эндпоинты ниже.
2. **Отзывы**: после завершения визита клиент получает в Telegram ссылку на форму отзыва. В
   админке для этого ничего делать не нужно — новые отзывы, как и раньше, появляются в
   «Огляд → Відгуки» (и приходят событием `review.created` по WebSocket). Форма отзыва — на
   публичном сайте записи (отдельный проект, см. конец брифа).

## Что сделать во фронтенде (`web/`)

Страница «Налаштування» — `/settings`, две вкладки: «Салон» и «Графік роботи». Остальные вкладки
старого UI (Профіль, Ролі та доступи, Загальні, Звіти) не делать: профиль — в «Мій профіль»,
остальное не переносим или ещё нет бекенда.

- Доступ: администратор и суперюзер. Мастеру раздела нет в меню, по прямой ссылке — 403
  (добавить раздел `settings` в `shared/auth/access.ts`).
- Пункт меню «Налаштування» и пункт «Налаштування» в меню профиля ведут сюда.
- Компоненты — как в COMPONENTS.md («Налаштування салону»): `ProForm` на странице и компонент
  недельного графика (тот же, что у сотрудников).

### Вкладка «Салон»

`GET /settings/salon` → `SalonInfoOut`:

| Поле | Подпись | Примечание |
| --- | --- | --- |
| `name` | Назва | Обязательное |
| `legalName` | Юридична назва | |
| `city` | Місто | |
| `address` | Адреса | |
| `phone` | Телефон | Маска `+380 (XX) XXX-XX-XX`, как в остальных формах |
| `email` | Email | Проверяется на бекенде |
| `website` | Сайт | |
| `instagram` | Instagram | |
| `facebook` | Facebook | |
| `openedOn` | Дата відкриття | `YYYY-MM-DD` |
| `description` | Короткий опис | До 2000 символов |

`PATCH /settings/salon` — отправлять только изменённые поля. Пустая строка или `null` очищает
поле (кроме `name` — пустое `name` → `422`). Некорректный email → `422` с текстом
«Некоректні поля: email». Ответ — обновлённый `SalonInfoOut`.

После смены названия обновить данные `/auth/me` (название в переключателе салона берётся оттуда):
инвалидировать запрос `me`.

### Вкладка «Графік роботи»

`GET /settings/schedule` → `{configured, week}`:

```jsonc
{
  "configured": true, // false — график ещё не заполняли (все дни — выходные)
  "week": {
    "monday": { "isWorkDay": true, "start": "09:00:00", "end": "20:00:00" },
    // … tuesday … saturday
    "sunday": { "isWorkDay": false, "start": null, "end": null }
  }
}
```

`PUT /settings/schedule` с телом `{week}` — **все семь дней** (`monday`…`sunday`), иначе `422`.
Для рабочего дня нужны `start` и `end`, `start < end`; у выходного время можно не слать (бекенд
обнулит). Ошибки валидации — `422`, `details` по полям.

UI (как в старом UI): для каждого дня — «Працює» / «Вихідний» и часы з / по; «Копіювати на всі
дні». Если `configured = false` — подсказка «Графік ще не заповнено». Перерыва у салона нет.

Важно: график салона пока **ни на что не влияет** — сетка Розкладу и свободное время считаются
по графикам мастеров (`GET /schedule`).

## Для сайта записи (не `web/`, отдельный проект)

- `GET /api/booking/{slug}/salon` теперь отдаёт ещё `city, address, phone, email, website,
  instagram, facebook, description` и `schedule` (по дням недели, `null` — не заполнен); поля в
  snake_case, как во всём Booking API.
- Страница отзыва `{сайт записи}/{slug}/review?token=<uuid>` — ссылку получает клиент:
  - `GET /api/booking/{slug}/reviews/{token}` → `{salon_name, master_name, services, visit_at}`;
    `404` — ссылка использована или недействительна;
  - `POST /api/booking/{slug}/reviews` с `{token, rating (1–5), text?}` → `201`.
