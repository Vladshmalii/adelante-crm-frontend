# Бриф для фронтенда: API для Розкладу

Бекенд реализовал ТЗ `web/docs/BACKEND_CALENDAR.md` (2026-09-29). Бекенд не менять. После
`npm run api:generate` всё ниже есть в `schema.gen.ts`.

Общее: префикс `/api/admin/v1`, заголовок `X-Salon-Id`, ответ `{data}`, camelCase. Даты
`YYYY-MM-DD` — по Киеву, время окон — `HH:MM:SS` по Киеву. Тексты ошибок (`message`) на украинском.

## 1. Способы оплаты для приёма оплаты визита

`GET /payment-methods` → `[{id, name, type}]`

- Администратор и суперюзер; мастеру `403`.
- Только способы, через которые оплата пройдёт (способ активен, есть касса, касса не выключена).
  Порядок — как в «Фінанси → Методи оплат».
- `type`: `cash | card | online | certificate | bonus | tips | other` — для иконки.
- Использовать в модалке оплаты визита вместо `GET /finances/payment-methods` (тот — только
  суперюзеру).

## 2. Графики работы на период

`GET /schedule?dateFrom=&dateTo=&masterId=`

- Даты включительно, период не больше 62 дней; `dateTo < dateFrom` или больше 62 дней → `422`.
- Без `masterId` — все не уволенные мастера (включая отпуск и больничный). Администраторов нет.
- Мастер получает только свой график; чужой `masterId` → `403`.

```jsonc
[
  {
    "masterId": "…",
    "name": "Анна Коваль",
    "color": "#ff0000", // или null
    "days": [
      {
        "date": "2026-09-28",
        "isWorkDay": true,
        "windows": [{ "start": "09:00:00", "end": "13:00:00" }, { "start": "14:00:00", "end": "18:00:00" }],
        "exception": null // или {"type": "vacation|sick|day_off|extra_shift", "comment": "…"}
      }
    ]
  }
]
```

- Перерыв уже вырезан из `windows`. Вне окон — нерабочее время (серым в сетке).
- В день отпуска, больничного или выходного `windows = []`, в `exception` — причина (можно
  подписать колонку). Доп. смена (`extra_shift`) — её часы в `windows`.
- Фильтр «Сьогодні» — мастера с `isWorkDay` на выбранную дату (или с записями).
- Колонки и цвета мастеров — отсюда (мастеру `/staff` закрыт).

**Изменение в исключениях графика** («Співробітники → Графік»): исключения одного сотрудника
больше не могут пересекаться. `POST` и `PATCH /staff/{id}/schedule/exceptions…` возвращают `409` с
текстом «Перетинається з іншим винятком: 01.03.2031–10.03.2031» — показать пользователю.

## 3. Сводка записей по дням

`GET /records/daily-summary?dateFrom=&dateTo=&masterId=`

- Даты включительно, не больше 62 дней. Каждый день периода есть в ответе, даже без записей.
- Отменённые записи не считаются; «Не прийшов» считаются. Запись относится ко дню начала.
- Мастер — только свои записи (чужой `masterId` → `403`), очереди «Без майстра» у него нет.

```jsonc
[
  {
    "date": "2026-09-28",
    "total": 5,
    "bookedMinutes": 300,
    "workMinutes": 960, // рабочее время всех не уволенных мастеров (или выбранного)
    "byMaster": [
      // только мастера с записями, по убыванию числа записей; очередь — последней
      { "masterId": "…", "count": 2, "bookedMinutes": 120, "workMinutes": 480 },
      { "masterId": null, "count": 1, "bookedMinutes": 60, "workMinutes": null }
    ]
  }
]
```

- Вид «Місяць»: до трёх элементов `byMaster` с `count` и «+N ще»; имена — из `GET /schedule`.
- Кольцо загруженности в мини-календаре: `bookedMinutes / workMinutes` (при `workMinutes = 0` —
  день нерабочий).

## 4. Напоминание о визите

В `RecordOut` (списки, карточка, ответы изменения записи):

| Поле | Смысл |
| --- | --- |
| `reminderEnabled` | Отправлять ли клиенту напоминание в Telegram за 30 минут |
| `reminderSentAt` | Когда ушло; `null` — ещё не отправлялось |
| `clientTelegramLinked` | Клиент привязан к боту; без этого напоминание не дойдёт |

- `POST /records` и `PATCH /records/{id}` принимают `reminderEnabled` (по умолчанию `true`).
  Права — как на остальные поля записи (мастер — по своей записи). `null` → `422`.
- После переноса записи на будущее время `reminderSentAt` снова `null` — напоминание уйдёт к новому
  времени.
- Напоминание получает клиент, который записал, даже если запись «для іншої людини».
- В `ClientOut` (`GET /clients`, `GET /clients/{id}`) — `telegramLinked`.

Блок «Сповіщення про візит» в карточке записи:

- выключатель `reminderEnabled`;
- статус: «Надіслано 28.09 о 13:30» (`reminderSentAt`) / «Буде надіслано за 30 хв до візиту» /
  «Клієнт не підключений до Telegram-бота» (`clientTelegramLinked = false`) / «Вимкнено».

## 5. Отмена списания расходника

`DELETE /records/{id}/consumables/{movementId}` → `200`, обновлённый список расходников записи.

- Товар возвращается на склад обратным движением (в истории товара — «Надходження» с причиной
  «Скасування списання: <клієнт>»).
- Можно по любой записи, в том числе завершённой и оплаченной, и для удалённого товара.
- Права — как у списания: администратор; мастер — по своей записи (чужая → `404`).
- Повторная отмена → `409`; `movementId` не из этой записи → `404`.

`GET /records/{id}/consumables` и `POST` теперь отдают отменённые списания с отметкой:

```jsonc
{
  "movementId": "…", "productId": "…", "productName": "Шампунь", "unit": "ml",
  "quantity": "150.000", "author": {"id": "…", "name": "…"}, "createdAt": "…",
  "cancelled": true, "cancelledAt": "…", "cancelledBy": {"id": "…", "name": "…"}
}
```

Показывать отменённые зачёркнутыми, без кнопки «Скасувати».
