# ТЗ: смены сотрудников по дням (2026-09-29)

Статус: **реализовано 2026-09-29** (`app/services/shifts.py`, `app/api/admin/shifts.py`,
миграция `a8c2e4f6b1d3`, тесты `tests/test_shifts.py`). Бриф для фронтенда —
[frontend-shifts.md](./frontend-shifts.md). Уточнения, принятые при реализации, — в конце.

## Зачем

Сейчас рабочее время задаётся недельным шаблоном (`staff_schedules`) и исключениями на периоды
(`schedule_exceptions`); график администраторов хранится, но ни на что не влияет. Заказчику нужен
график **по дням**: горизонтальная сетка — сотрудники по строкам, даты по столбцам, в ячейке смена
«09:00–18:00» или отметка «Відпустка» / «Лікарняний». По клику — поставить или изменить смену и
увидеть записи мастера на этот день.

## Решения заказчика

| # | Вопрос | Решение |
| --- | --- | --- |
| 1 | Недельный шаблон | Не хранится. Вместо него — массовое заполнение смен на период |
| 2 | Перерыв в смене | Есть, необязательный |
| 3 | Смен в день | Одна |
| 4 | Отпуск, больничный | Отметка в ячейке графика («галочка» відпустка / лікарняний). Выходной — пустая ячейка |
| 5 | Статусы сотрудника в профиле | Только «активний» и «звільнений»; «у відпустці» и «на лікарняному» убираются |
| 6 | Особые дни салона (праздники) | Не нужны — границы смен только по недельному графику салона |
| 7 | Запись вне смены | Разрешать (в том числе когда салон закрыт): в Розкладе администратор может добавить мастеру запись в нерабочее время, мастер — себе. Запись получает признак `outsideShift` (только для отображения). **В дни відпустки і лікарняного — запрещено** |
| 8 | Сократить или удалить смену, когда есть записи | Запрещать |
| 9 | Уведомления администраторам | Новая запись, перенос, отмена — только администраторам, которые сейчас на смене (перерыв не учитывается); никого на смене — никому; суперюзер получает всегда |
| 10 | Кто редактирует смены | Суперюзер — всех; администратор — свои и мастеров; мастер — только свои. Если смену или отметку мастера поменял не он сам — мастеру уведомление в Telegram |
| 11 | Кто видит сетку | Суперюзер и администратор — всех; мастер — только себя |
| 12 | Окно записи на сайте | 30 дней вперёд (сейчас 90). Ставить смены дальше 30 дней — можно |
| 13 | Смены в прошлом | Ставить и менять нельзя никому (сегодня — можно) |
| 14 | Часы салона изменились, смены вне новых часов | Смены обрезаются по новым часам, кроме смен, у которых на обрезаемое время есть записи — такие не меняются и возвращаются как конфликты |
| 15 | Салон без графика работы | Смены ставить нельзя, пока график салона не заполнен |
| 16 | Массовое заполнение | И смены, и отметки на период |
| 17 | Перенос текущих графиков | Не нужен: БД пустая, суперюзер заполнит смены сам |
| 18 | Порядок строк | Сначала мастера, потом администраторы; уволенные не показываются, их прошлые смены сохраняются |

## Модель (шард)

`StaffShift` — одна строка на сотрудника и дату (unique `staff_id + date`):

| Поле | Смысл |
| --- | --- |
| `staff_id` | Мастер или администратор (id из Master DB) |
| `date` | Дата по Киеву |
| `kind` | `shift` (смена) / `vacation` (відпустка) / `sick` (лікарняний) |
| `start`, `end` | Время смены (только для `shift`) |
| `break_start`, `break_end` | Необязательный перерыв внутри смены |
| `comment` | Комментарий |
| `updated_by`, `updated_by_name`, `updated_at` | Кто и когда менял |

Удаляются (данных нет, одна миграция):

- таблицы `staff_schedules`, `schedule_exceptions` и эндпоинты `/staff/{id}/schedule*`;
- статусы `vacation` и `sick` у `StaffProfile.status` (остаются `active`, `fired`); фильтр
  `GET /staff?status=` — только эти два значения.

## Бизнес-правила

1. **Рабочее время дня = смена** (`kind = shift`) минус перерыв. Нет строки или отметка — не
   работает.
2. **Границы — часы салона** (`/settings/schedule`) в этот день недели: `start ≥ открытие`,
   `end ≤ закрытие`, `start < end`; перерыв внутри смены. Салон в этот день закрыт или график салона
   не заполнен — смену поставить нельзя (`422`). Отметки (відпустка, лікарняний) ставятся на любой
   день.
3. **Одна строка на сотрудника и дату**: смена или отметка.
4. **Прошлое не меняется:** дата раньше сегодняшней (по Киеву) — `422` для всех, включая суперюзера.
5. **Записи и смена мастера:**
   - запись вне смены — разрешена: в Розкладе администратор может поставить мастеру запись в
     нерабочее время, мастер — себе, в том числе когда салон закрыт (проверки смены при создании и
     переносе записи из админки нет, как и сейчас);
   - **день відпустки або лікарняного** — запись мастеру на этот день нельзя создать, перенести
     на него или назначить на неё этого мастера (`409` «Майстер у відпустці 05.10»). Запись без
     мастера — можно;
   - поставить отметку відпустка / лікарняний на день, где у мастера есть записи (кроме
     отменённых), — `409` со списком записей;
   - в `RecordOut` — признак `outsideShift: bool`: запись (без учёта перерыва) не помещается целиком
     в смену мастера этого дня или смены нет. Только для отображения и предупреждения в Розкладе;
     у записи без мастера — `false`;
   - удалить смену, заменить её отметкой или сократить так, что запись, которая была внутри смены,
     окажется вне неё, — `409` со списком записей (время, клиент). Записи, которые уже были вне
     смены, изменению не мешают; отменённые не считаются.
6. **Изменение часов салона** (`PUT /settings/schedule`) обрезает смены на будущие даты (с сегодня)
   по новым часам: начало — не раньше открытия, конец — не позже закрытия, перерыв — внутри. Если
   салон в этот день недели теперь закрыт или от смены ничего не осталось — смена удаляется.
   **Исключение:** если на обрезаемое время у мастера есть записи (кроме отменённых), эта смена не
   меняется. Часы салона сохраняются в любом случае; ответ `PUT /settings/schedule` содержит отчёт:
   сколько смен обрезано и удалено, и список конфликтов (сотрудник, дата, записи), которые нужно
   разрешить вручную — перенести записи и поправить смену. Изменения смен — в журнал.
7. **Публичная запись (сайт)** — только внутри смен; окно записи — 30 дней вперёд.
8. **Права:**
   - редактирование: суперюзер — все; администратор — свои и мастеров (смены других
     администраторов — `403`); мастер — только свои;
   - просмотр: суперюзер и администратор — все; мастер — только свои.
9. **Журнал:** каждое изменение смены или отметки — в `audit_log` (`entity = "shift"`).
10. **Уведомление мастеру:** если его смену или отметку поставил, изменил или удалил не он сам
   (вручную или массовым заполнением), мастеру в Telegram: «Вашу зміну на 05.10 змінено:
   10:00–19:00» / «…видалено» / «05.10–14.10: відпустка». Массовое заполнение — одно сообщение со
   сводкой на мастера, а не по сообщению на день.
11. **Время** — по Киеву.

## Массовое заполнение

`POST /shifts/fill` — для одного или нескольких сотрудников (с учётом прав из п. 8):

- период `dateFrom`–`dateTo` (с сегодня; не больше 62 дней за раз);
- что ставить — один из вариантов:
  - **по дням недели** — для каждого дня недели смена `start–end` (+ перерыв) или пусто;
  - **цикл** — N рабочих дней / M выходных (2/2, 3/3, 5/2…) со стартовой даты, со временем смены;
  - **скопировать период** — повторить смены и отметки с другого периода (например, прошлой недели);
  - **отметка на период** — відпустка или лікарняний на все дни периода;
- режим для дней, где уже есть смена или отметка: не трогать / перезаписать;
- пропускаются с причиной в отчёте: дни, где салон закрыт (для смен); дни, где перезапись
  запрещена из-за записей (п. 5); дни с записями — для отметок відпустка / лікарняний;
- ответ — отчёт: создано, изменено, пропущено (дата, сотрудник, причина).

## Уведомления администраторам

События: новая запись, перенос, отмена (сейчас администраторы получают новые записи всегда, а перенос
и отмену — только по записям без мастера).

- Получатели: администраторы салона, у которых **в момент отправки** идёт смена
  (`start ≤ сейчас < end` по Киеву, перерыв не учитывается), и все суперюзеры салона — всегда.
- Никого на смене и суперюзеров с Telegram нет — не отправляется.
- Автору изменения — не отправляется (как сейчас).
- Мастер получает уведомления о своих записях как сейчас, независимо от смены.

## API (набросок)

| Метод и путь | Что |
| --- | --- |
| `GET /shifts?dateFrom&dateTo` | Сетка: строки — сотрудники (мастера, потом администраторы; `id, name, role, color`), ячейки — смена или отметка; для мастеров — число записей в день. Период — не больше 62 дней |
| `PUT /shifts/{staffId}/{date}` | Поставить или изменить смену / отметку |
| `DELETE /shifts/{staffId}/{date}` | Убрать (`409`, если мешают записи) |
| `POST /shifts/fill` | Массовое заполнение, отчёт |
| `GET /records?masterId&dateFrom&dateTo` | Записи в ячейке — существующий эндпоинт |

Переделываются на смены: `GET /schedule`, `GET /records/daily-summary`, `GET /masters/{id}/slots`,
Booking API (`/slots`, `/availability`, `POST /records`), уведомления администраторам,
`PUT /settings/schedule` (обрезка смен). Бриф фронтенда `frontend-calendar.md` обновить.

## Уточнения при реализации

- Суперюзер — тоже администратор салона и есть в сетке отдельной строкой.
- При увольнении будущие смены сотрудника удаляются (прошлые остаются).
- `outsideShift` и проверки «запись внутри смены» перерыв не учитывают: запись на время перерыва
  считается внутри смены.
- Уведомление администраторам о переносе — только если изменилось время записи (замена услуг без
  смены времени — не перенос).
- Массовое заполнение, режим `copy`: исходный период повторяется циклически; пустой день источника
  — выходной (с `overwrite` очищает день, без — не трогает).
- Ошибки смен — `{message, code, details}`; `code`: `past`, `salon_not_configured`, `salon_closed`,
  `outside_salon_hours`, `has_records` (`details.records` — записи, которые мешают).
- Событие `shift.changed` уходит и в WebSocket (обновить сетку); мастеру — только о его сменах.
