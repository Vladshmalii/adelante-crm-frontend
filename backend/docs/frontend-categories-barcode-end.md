# Бриф для фронтенда: категории услуг, штрихкод, маржа, конец записи

Бекенд реализовал ТЗ `web/docs/BACKEND_CATEGORIES_BARCODE_RESIZE.md` (2026-10-03) — контракт как в
ТЗ, после выката `npm run api:generate`. Бекенд не менять. Ниже — только то, что ТЗ не описывало
или где поведение стоит знать.

## Отличия и уточнения

1. **Категория у услуг внутри записи** (`RecordOut.services[].category`) — теперь тоже объект
   `{id, name}` (было строкой). Поправить места, где она показывается или по ней группируют.
2. **`PATCH /services/{id}` с `categoryId: null`** — услуга переходит в «Інше».
3. **Названия категорий** — пробелы по краям обрезаются; пустое — `422`. Порядок в
   `GET /services/categories` — по украинскому алфавиту («Ґ» после «Г», «І» после «И»), «Інше» —
   последней; сортировать на фронте не нужно.
4. **Ручная длительность записи и `serviceIds`.** Если форма шлёт `serviceIds` без изменений —
   длительность (заданная растягиванием или полем «Кінець») сохраняется. Сбрасывается на сумму
   услуг только когда состав услуг изменился и `endAt` не передан.
5. **Ошибки `endAt`** (`422`): «Кінець запису має бути пізніше за початок», «Кінець запису має бути
   в той самий день, що й початок». Ровно 00:00 следующего дня — допустимо.
6. **Импорт склада** читает колонки по заголовкам, порядок любой: `Назва, Артикул, Штрихкод,
   Категорія, Одиниця, Об'єм упаковки, Залишок, Мін. залишок, Собівартість, Ціна продажу, Опис`.
   Шаблон собирать в этом порядке («Штрихкод» после «Артикул»). Ошибка дубля штрихкода в отчёте:
   «Рядок 4: штрихкод «…» вже є у товару «Шампунь» (BC-1)».
7. **Штрихкод** длиннее 64 символов — `422` «Штрихкод — не довше 64 символів»; дубликат — `409`
   «Товар з таким штрихкодом вже існує» (в том числе у неактивного товара).
8. **Поиск по штрихкоду** — подстрока (`query=3456` найдёт `4820000123456`), работает и для мастера
   при выборе расходников; сам штрихкод мастеру не отдаётся (`barcode: null`).
