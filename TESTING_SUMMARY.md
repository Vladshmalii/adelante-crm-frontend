### 4. Finances (был подключён процентов на 10)
- Переписан `lib/api/finances.ts` под реальную схему бэкенда (были мок-эпохи типы:
  неправильные enum'ы операций/документов, произвольный текст вместо ссылок на
  кассы/методы оплаты).
- Подключены к реальным данным: Dashboard (KPI), Операции (создание+правка), Документы
  (создание+правка), Методы оплаты (создание+правка+переключение+деактивация), Кассы
  (создание), Чеки (создание+сторно). Всё проверено вживую с реальным бэкендом.
- **Бэкенд-баг 1**: создание чека падало с 500 (`MissingGreenlet` — синхронный доступ к
  ленивой `selectin`-связи на только что созданном объекте). Исправлено в
  `backend/app/api/admin/finances.py` (`flush()` + `refresh(..., attribute_names=["payments"])`).
- **Бэкенд-баг 2**: `client.id` в чеке рендерился как строка `"None"` вместо `null`.
  Исправлено там же.
- **Фронт-баг**: статус документа не отображался — маппинг ссылался на несуществующий
  статус `completed` вместо реальных `issued`/`paid`. Исправлено в `DocumentRow.tsx` и
  `DocumentDetailsModal.tsx`.
- **Системный баг с датами**: `DatePicker` отдаёт `"YYYY-MM-DD"` без времени/зоны; при
  отправке на бэкенд без явного `Z` дата сдвигалась на день в зависимости от таймзоны
  сервера. Исправлено на всех точках создания/правки в Finances (операции, документы,
  чеки, дашборд) — везде теперь явный `T00:00:00.000Z`.
- Пофикшено отображение кассы в списке методов оплаты (бэкенд отдаёт только
  `cashRegisterId`, имя резолвится на фронте через список касс).
- Подключена ранее «сиротская» модалка `CreateCashRegisterModal` в Payment Methods.

Оба бэкенд-фикса потребовали ручного перезапуска uvicorn (процесс поднят без `--reload`).

### 5. Переключатель салона (текущая задача)
Раньше в левом верхнем углу был статичный логотип + текст «Adelante CRM»; в коде был
явный комментарий «мультисалонный UI-переключатель не сделан — всегда берём первый
салон». Реализовано:
- Новый компонент `ui/src/shared/components/layout/SalonSwitcher.tsx` — тот же
  паттерн portal/click-outside, что уже используется в `ProfileDropdown`. Показывает имя
  текущего салона; если у пользователя салонов ≥ 2, появляется шеврон и дропдаун со
  списком (галочка на активном).
- Выбор другого салона → `apiClient.setSalonId()` + `window.location.reload()`
  (простой и надёжный способ обновить все данные, т.к. глобального механизма
  реактивного рефетча по смене тенанта в проекте нет).
- В `useAuthStore` добавлено поле `currentSalonId` (персистентное) — переключатель
  реагирует на него реактивно, а не читает `localStorage` напрямую.
- `useAuth.ts` (`applySalon`) при логине/`checkAuth` теперь сохраняет предыдущий выбор
  пользователя, если он всё ещё есть в списке его салонов, иначе берёт первый — раньше
  всегда брался первый.

**Проверено вживую**: typecheck чистый; в браузере со реальным бэкендом (у тестового
аккаунта только один салон «Demo Salon») переключатель корректно показывает имя без
шеврона и не реагирует на клик — то есть корректно ведёт себя в единственно доступном
на сейчас сценарии. Сворачивание/разворачивание сайдбара с переключателем работает
как раньше с логотипом.

**Не проверено вживую**: сам процесс переключения между двумя реальными салонами —
у текущего тестового пользователя в базе только один салон, второго для проверки нет.
Логика дропдана скопирована с уже рабочего `ProfileDropdown`, но полноценно провести
через реальный клик "выбрать другой салон → данные обновились" не удалось.
