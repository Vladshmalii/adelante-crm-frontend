# Функционал страниц Adelante CRM

Спецификация для переноса старого фронтенда (`ui/`, Next.js) на новый (`web/`).
Собрана по коду `ui/src` на 2026-09-23 и сверена с OpenAPI бекенда (`backend/`, 43 эндпоинта).

Не входят: публичная запись `/booking` (отдельный проект, позже), витрина компонентов `/ui-demo`
и `/demo-500`.

Тексты интерфейса приведены как в старом UI (украинский) — по ним удобно искать место в коде.

## Как читать статусы

| Статус                    | Значение                                                                                                           |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **API**                   | Эндпоинт есть на бекенде, старый UI его вызывает                                                                   |
| **API (не используется)** | Эндпоинт есть на бекенде, но старый UI его не вызывает или вызывает не полностью                                   |
| **мок**                   | Бекенда нет: данные захардкожены (`data/mock*.ts`) или живут только в локальном стейте и теряются при перезагрузке |
| **заглушка**              | Элемент нарисован, но ничего не делает (`console.log`, пустой обработчик, статичные цифры)                         |

Пути эндпоинтов ниже указаны без префикса `/api/admin/v1`. Все салонные эндпоинты требуют заголовок
`X-Salon-Id`.

### Модалка «Мій профіль»

Открывается из меню профиля на любой странице. Тот же компонент — вкладка «Профіль» в Налаштуваннях.

- Поля: имя, фамилия, email, телефон, дата рождения, дата приёма (только чтение).
- Блок по роли: для мастера — спеціалізація, графік, оклад и комісія (только чтение);
  для администратора — спеціалізація, графік, оклад; для менеджера — оклад, графік.
- «Додаткова інформація»: адреса, контактна особа и телефон на экстренный случай.
- Какие поля можно редактировать, зависит от роли (мастер — только контакты и адрес).
- Интеграция с Telegram: статус подключения и кнопка «Підключити» (deep link `t.me/AdelanteCrmBot?start=<id>`).
- Статус: данные — API (`/auth/me`), **сохранение — заглушка** (`console.log`). На бекенде нет
  эндпоинта обновления своего профиля.

### Сквозные правила

- **Маскирование персональных данных.** В таблицах телефон показывается как `•••• 1234`, email —
  `••••`; в карточках клиента и сотрудника полные ФИО, телефон и email раскрываются кнопкой
  «глаз» только для администратора. Роль берётся из мок-профиля, а не из `/auth/me`.
- **Права доступа.** Есть хук `usePermissions` с матрицей прав, но он **нигде не используется**.
  Реальные права на фронте не проверяются.
- **Валюта** — гривна (`₴`), формат чисел `uk-UA`, даты `ДД.ММ.РРРР`.

## 1. Вход и доступ

### `/login` — Вхід

| Функция                 | Детали                                                    | Статус                   |
| ----------------------- | --------------------------------------------------------- | ------------------------ |
| Вход по email и паролю  | Валидация на пустые поля; после входа — переход в Розклад | API (`POST /auth/login`) |
| Ссылка «Перший вхід?»   | Ведёт на `/setup`                                         | —                        |
| Ссылка «Забули пароль?» | Ведёт на `/forgot-password`                               | —                        |
| «Увійти через Telegram» | Кнопка без действия                                       | заглушка                 |
| Промо-блок слева        | Статичный текст о продукте                                | —                        |

Токены: access и refresh хранятся в `localStorage`, access дублируется в cookie для `middleware.ts`.
Перед запросом просроченный access обновляется через `POST /auth/refresh`.

### `/forgot-password` — Відновлення доступу

- Поле email → «Надіслати посилання» → экран «Посилання надіслано» со ссылкой на вход.
- Статус: **заглушка** — запрос не отправляется, только тост. На бекенде есть
  `POST /auth/forgot-password` (**API (не используется)**).

### `/reset-password` — Новий пароль

- Новый пароль (минимум 8 символов) и подтверждение → экран успеха со ссылкой на вход.
- Статус: **заглушка** — запрос не отправляется, токен из ссылки письма не читается.
  На бекенде есть `POST /auth/reset-password` (**API (не используется)**).

### `/setup` — Перша реєстрація

- Сотрудник по своему email задаёт пароль при первом входе.
- Статус: **заглушка** — `authApi.setup` всегда бросает ошибку, на бекенде такого эндпоинта нет.

## 2. Розклад — `/calendar`

Главный рабочий экран, открывается по умолчанию (`/` → `/calendar`).
Параметры URL: `?date=YYYY-MM-DD` — открыть дату, `?create=…` — сразу открыть создание записи.

### Шапка календаря

| Функция                    | Детали                                                            |
| -------------------------- | ----------------------------------------------------------------- |
| Навигация по датам         | «←», «Сьогодні», «→»; шаг зависит от вида (день / неделя / месяц) |
| Текущая дата               | День недели и дата крупно                                         |
| Переключатель вида         | День / Тиждень / Місяць                                           |
| Поиск, сповіщення, профиль | Как в общей шапке                                                 |

### Панель фильтров

| Функция               | Детали                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------- |
| Категории сотрудников | Усі / Сьогодні (у кого есть записи на дату, со счётчиком) / Майстри / Адміністрація          |
| Выбор сотрудников     | Чипы с именем и ролью; «Усіх у групі», «Усіх», «Очистити». По умолчанию выбраны все активные |
| Шаг сетки             | 5 / 15 / 30 / 60 минут (по умолчанию 30)                                                     |

### Вид «День» (основной)

- Колонки: «Без майстра» (очередь записей без мастера) + по колонке на каждого выбранного сотрудника.
- Шкала времени с 08:00; сетка продлевается, если есть записи позже 19:00; после 19:00 слоты помечены как нерабочие.
- Линия «ЗАРАЗ» на текущем времени; при открытии прокрутка к текущему часу.
- Клик по свободному слоту → создание записи с подставленными мастером и временем.
- Пересекающиеся записи одного мастера рисуются стопкой со смещением.
- Автоматические карточки «Перерва» для промежутков до 15 минут между записями.
- Карточка записи: время начала, услуга, иконка статуса, имя клиента (или гостя с пометкой
  «(Гість)»), замаскированный телефон, комментарий (на высоких карточках). Цвет — по уровню
  важности: стандартний / важливий / особливий.
- Мобильная версия — список записей по мастерам.

### Вид «Тиждень»

- Таблица: строки — сотрудники (+ «Без майстра»), столбцы — 7 дней недели с понедельника.
- В ячейке — карточки записей (время, иконка статуса, услуга, клиент). Клик — детали записи.
- **Баг:** записи загружаются только за текущий день, поэтому остальные дни недели пустые.

### Вид «Місяць»

- Сетка месяца; в дне — до 3 сотрудников с количеством записей и «+N ще».
- Клик по дню с записями → модалка со списком записей дня; по пустому дню → переход в вид «День».
- **Баг:** та же проблема — данные только за один день.

### Создание записи (правая панель «Новий запис»)

| Поле / функция           | Детали                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Майстер                  | Поиск, группы «Черга» (Без майстра) / Майстри / Адміністрація                                                                               |
| Дата                     | Выбор даты                                                                                                                                  |
| Час початку и закінчення | Конец считается автоматически по сумме длительностей услуг (по умолчанию 30 мин); конец не может быть раньше начала                         |
| Проверка занятости       | «Цей час вже зайнятий майстром» + кнопка «Знайти вільний час» (ищет ближайшее окно нужной длительности с шагом 15 минут на 12 часов вперёд) |
| Послуги                  | Мультивыбор с поиском, группировкой по категориям, показом «хв • грн»                                                                       |
| Ціна                     | Сумма услуг, правится вручную и кнопками ±50                                                                                                |
| Тривалість               | Сумма длительностей услуг                                                                                                                   |
| Коментар                 | Свободный текст («Особливі побажання, алергії…»)                                                                                            |
| Рівень                   | Стандартний / Важливий / Особливий                                                                                                          |
| Пошук клієнта            | По имени или последним 4 цифрам телефона (от 3 символов, задержка 300 мс); карточка найденного клиента — визиты, сегмент, «Скинути»         |

- одна услуга на запись — уходит только первая выбранная;

Свободные слоты мастера на бекенде есть (`GET /masters/{id}/slots`) — **API (не используется)**,
поиск свободного времени сделан на клиенте.

### Завершение визита (модалка «Завершення візиту»)

- Нотатки майстра про клієнта, фото процедуры (до 10 шт., до 5 МБ).
- Статус: **API** (`POST /records/{id}/complete`), но:
  - оплаты уходят пустым списком — выбора способа оплаты нет, хотя бекенд принимает
    `payments[{paymentMethodId, amount}]`;
  - фото не загружаются на сервер (`POST /uploads` есть), в `photoUrls` ничего не уходит.

### Редактирование записи (модалка «Редагувати запис»)

- Майстер, ім'я клієнта, телефон, послуга (текстом), дата, час початку и закінчення, тип, статус, ціна, нотатки, «Видалити».
- Статус: **API** (`PATCH /records/{id}` + смена статуса отдельно). Бекенд принимает только
  `startAt, masterId, serviceId, importance, comment, internalNotes, visitorName, visitorPhone` —
  имя и телефон клиента, текст услуги и цена из формы фактически не сохраняются.

### Карточка сотрудника

Имя, бейджи роли и статуса, контакты (раскрытие для администратора), дата приёма, спеціалізація,
графік (текстом), зарплата, комісія; кнопки «Редагувати» и «Видалити».

### Создание и редактирование сотрудника

### Статистика (модалка)

- Виручка (завершені візити), Завершених візитів, Середній чек, Середній рейтинг.
- Статус: **API** (`GET /staff/{id}/stats`). Бекенд умеет период (`dateFrom/dateTo`), UI его не передаёт.

## 12. Что учесть при переносе

### Баги и недоделки старого UI, которые не надо переносить

1. В Розкладі недельный и месячный виды показывают только записи текущего дня.
2. Фильтры-выпадашки в Клієнтах и Співробітниках не применяются.
3. Ссылки `/clients?id=…` (из поиска и из записи) не открывают карточку клиента.
4. Восстановление пароля не отправляет запросы, хотя бекенд готов.
5. Завершение визита не передаёт оплаты и фото.
6. Уведомления из WebSocket не выводятся в колокольчик.
7. Роль пользователя для маскирования данных берётся из мока, а не из `/auth/me`.
8. Во многих формах сохраняются поля, которые бекенд игнорирует (цена записи, стать сотрудника,
   «Продано / Сплачено» клиента и т. п.).
9. Фильтрация и поиск часто сделаны на клиенте поверх одной страницы данных, хотя бекенд
   фильтрует сам (услуги, операции, документы, чеки).

### Возможности бекенда, которых нет в старом UI

- `GET /masters/{id}/slots` — свободные слоты мастера для записи.
- `POST /uploads` — загрузка файлов (фото визита, аватары).
- `POST /staff/{id}/schedule/exceptions` — отпуск, больничный, выходной, доп. смена.
- `GET /services/categories` — фактические категории услуг.
- `GET /finances/export` — экспорт финансов.
- Полный `GET /finances/dashboard` — выручка по дням, расходы по категориям, разбивка оплат, топ услуг.
- `POST /clients/import` возвращает отчёт об импорте (`created, updated, errors`).

### Мёртвый код (не переносить)

`AddRecordModal`, `EditRecordModal`, `OverviewTabs` (Огляд), `EditReceiptModal`, `EditCashRegisterModal`
(Фінанси), `ServicesHeader`, скелетоны `CalendarSkeleton` и `ClientsTableSkeleton`, графики
`ClientsChart`, `StaffPerformanceChart`, `ServicesPopularityChart`, хук `usePermissions`,
зависимость `@dnd-kit/*` (перетаскивания записей в календаре нет).

### Принятые решения (2026-09-23)

1. **Роли — две фиксированные**, как на бекенде: `administrator` и `master`. Матрицу прав из старого UI
   (вкладка «Ролі та доступи», `permissions.config.ts`) не переносим. Права на фронте проверяются
   по роли из `GET /auth/me`.
2. **В одной записи можно выбрать несколько услуг.** Длительность и цена записи — сумма по услугам.
3. **Запись без мастера поддерживается**: колонка «Без майстра» (очередь) в календаре, выбор
   «Без майстра» при создании и редактировании, возможность позже назначить мастера.
4. **Разделы без бекенда ждут бекенд.** Склад, Лояльність, Звіти, настройки салона и профиля не
   переносим на моках; делаем, когда появятся эндпоинты. В меню раздел появляется вместе с рабочей
   страницей.
5. **Типы финансовых операций — как на бекенде:** `income` (Прихід), `expense` (Видаток),
   `transfer` (Переказ). Типы старого UI (Платіж / Повернення / Видача / Внесення) не переносим.
6. **Блоки карточки записи делаем:** повторение записи, сповіщення про візит, списання витрат
   (ресурсы — отложены, см. п. 9).
   Блок «Лояльність» клиента не делаем. Списание расходников зависит от Складу, поэтому появится
   вместе с ним.
7. **Завершить и оплатить визит без мастера нельзя.** Кнопка «Завершити візит» недоступна, пока мастер
   не выбран; бекенд тоже должен отклонять `complete` для записи без мастера.
8. **Несколько услуг выполняет один мастер.** Услуги идут подряд у мастера записи; время и цена
   суммируются. Разные мастера на разные услуги одной записи не поддерживаем.
9. **Ресурсы откладываем.** Блок «Ресурси» в записи пока не делаем, вернёмся к нему отдельно.
10. **Напоминания о визите — пока только Telegram** (решение 2026-09-28): бот сам шлёт напоминание
    за 30 минут; в карточке записи — статус и выключатель «Не нагадувати». SMS и выбор времени — позже.
11. **Повторение записи отложено** (решение 2026-09-28). Когда вернёмся: каждые N дней или недель,
    окончание по дате или после N повторов; изменить или отменить одну запись или всю серию.
12. **Права доступа** — роли `master`, `administrator` и флаг `is_superuser` у администратора.
    Подробно — [ACCESS.md](./ACCESS.md). Маскирование телефонов и email из старого UI убираем.
13. **Завершение визита и оплата — отдельные шаги.** Мастер завершает визит (нотатки, фото), оплату
    проводит администратор.
14. **Часовой пояс — `Europe/Kyiv`** для всех дат и времени, независимо от браузера.
15. **Мобильной версии нет.** Интерфейс только для десктопа.
16. **Розклад — раскладка старого UI, стиль antd** (решение 2026-09-28, по демо старого фронта):
    мини-календарь с кольцами загрузки в меню; шапка (навигация, дата, День / Тиждень / Місяць);
    фильтры (Усі / Сьогодні, шаг 5–60 хв, чипы мастеров); сетка дня — колонки «Без майстра» и
    мастеров; неделя — строки-мастера × 7 дней; месяц — сетка с мастерами и «+N ще»; «Новий запис»
    и «Деталі запису» — широкие панели справа в три колонки. Сетки дня и недели — свои на CSS
    Grid (библиотеки не умеют строки-мастера в неделе); **перенос записи перетаскиванием** — сразу
    (`@dnd-kit`, с подтверждением). Колонок администраторов и группы «Адміністрація» нет — записи
    бывают только у мастеров. Не переносим: Ресурси, Закріплені / Розширені поля, лояльность,
    «Чат в WhatsApp».
17. **Порядок работ:**
    1. ✅ Клієнти, Співробітники, Послуги.
    2. ✅ Огляд и Фінанси.
    3. ✅ Розклад (бекенд — [BACKEND_CALENDAR.md](./BACKEND_CALENDAR.md)).
    4. ✅ Склад и Звіти; расходники по записи — в карточке записи в Огляді.
    5. ⏳ Налаштування — вне рамок пока.

    Вне плана сделаны (не требовали бекенда): восстановление пароля, уведомления в реальном
    времени, глобальный поиск, просмотр профиля.
