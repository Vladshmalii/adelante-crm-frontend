## Общее

- Префикс `/api/admin/v1`, заголовок `X-Salon-Id`, ответ `{data, meta?}`, поля camelCase.
- Числа-деньги и количества приходят **строками-десятичными** (`"1250.000"`, `"0.40"`) —
  форматировать через общие хелперы, не `parseFloat` для расчётов денег.
- Даты — ISO с зоной; показывать в `Europe/Kyiv` (`shared/lib/date.ts`). Параметры `dateFrom`,
  `dateTo` можно слать без зоны — бекенд считает время киевским.
- Ошибки `{message}` — уже на украинском, их можно показывать пользователю как есть.
- После `npm run api:generate` все эндпоинты ниже есть в `schema.gen.ts`.

## Склад — `/inventory`

### Модель товара

`ProductOut`:

| Поле                     | Тип                         | Смысл                                                         |
| ------------------------ | --------------------------- | ------------------------------------------------------------- |
| `id`, `name`             |                             |                                                               |
| `unit`                   | `pcs \| ml \| l \| g \| kg` | Единица учёта. Подписи: шт, мл, л, г, кг                      |
| `quantity`               | decimal                     | Остаток **в единице товара**                                  |
| `stockStatus`            | `in_stock \| low \| out`    | В наявності / Закінчується (`quantity ≤ minQuantity`) / Немає |
| `sku`                    | string                      | Артикул, уникальный без учёта регистра                        |
| `category`               | `{id, name}`                | Всегда есть; по умолчанию — системная «Без категорії»         |
| `packageVolume`          | decimal \| null             | Сколько единиц в упаковке (для мл/г/…)                        |
| `minQuantity`            | decimal                     | Мінімальний залишок                                           |
| `costPrice`, `salePrice` | decimal \| null             | Собівартість и ціна продажу за единицу                        |
| `description`            | string \| null              |                                                               |
| `isActive`               | bool                        | `false` — товар удалён (мягко)                                |
| `createdAt`              | datetime                    |                                                               |

Мастеру `GET /inventory/products` возвращает только активные товары и заполняет лишь `id, name,
unit, quantity, stockStatus` (остальное `null`) — для выбора товара при списании.

Отображение остатка «N шт + залишок» (как в старом UI): если `unit ≠ pcs` и есть `packageVolume` —
`floor(quantity / packageVolume)` упаковок и остаток `quantity mod packageVolume` в единице товара.

### Эндпоинты

| Метод и путь                                | Тело / параметры                                                                                                                                                                                                                 | Ответ                                                                                            |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `GET /inventory/products`                   | `query` (название или артикул), `categoryId`, `stockStatus`, `includeInactive` (bool), `sort` (`name \| sku \| quantity \| createdAt`), `desc` (bool), `page`, `perPage` (≤ 500)                                                 | `ProductOut[]` + `meta`                                                                          |
| `GET /inventory/summary`                    | —                                                                                                                                                                                                                                | `{total, low, out, stockValue}` — KPI (только активные; вартість = Σ собівартість × залишок)     |
| `GET /inventory/products/{id}`              | —                                                                                                                                                                                                                                | `ProductOut`                                                                                     |
| `POST /inventory/products`                  | `name*`, `sku*`, `categoryId`, `unit` (по умолч. `pcs`), `packageVolume` (> 0), `quantity` (начальный остаток ≥ 0 — станет движением «Надходження / Початковий залишок»), `minQuantity`, `costPrice`, `salePrice`, `description` | `201 ProductOut`; артикул занят → `409`                                                          |
| `PATCH /inventory/products/{id}`            | любые поля кроме `quantity` (игнорируется), плюс `isActive`; `name`, `sku`, `categoryId`, `unit`, `minQuantity`, `isActive` нельзя передать `null` → `422`                                                                       | `ProductOut`; артикул занят → `409`                                                              |
| `DELETE /inventory/products/{id}`           | —                                                                                                                                                                                                                                | `204`, мягкое удаление (`isActive = false`)                                                      |
| `POST /inventory/products/{id}/movements`   | `{type, quantity, reason?}` — см. ниже                                                                                                                                                                                           | `201 MovementOut`                                                                                |
| `GET /inventory/products/{id}/movements`    | `page`, `perPage`                                                                                                                                                                                                                | `MovementOut[]` (новые сверху) + `meta`                                                          |
| `GET /inventory/categories`                 | —                                                                                                                                                                                                                                | `[{id, name, isSystem, productsCount}]` (системная первой)                                       |
| `POST /inventory/categories`                | `{name}`                                                                                                                                                                                                                         | `201`; имя занято (без учёта регистра) → `409`                                                   |
| `PATCH /inventory/categories/{id}`          | `{name}`                                                                                                                                                                                                                         | переименование; системную → `409`                                                                |
| `DELETE /inventory/categories/{id}?mode=`   | `move_to_uncategorized` (по умолч.) или `delete_products`                                                                                                                                                                        | `204`; товары уходят в «Без категорії», при `delete_products` ещё и удаляются; системную → `409` |
| `POST /inventory/import`                    | `multipart/form-data`, поле `file` (.xlsx)                                                                                                                                                                                       | `{created, updated, errors[]}`                                                                   |
| `GET /inventory/export?blocks=&categoryId=` | `blocks` — через запятую из `main,stock,finance,description` (`main` всегда)                                                                                                                                                     | `.xlsx` (blob, `inventory.xlsx`)                                                                 |

**Движения** (`MovementIn`):

| `type`                                      | `quantity`                   | Результат                                  |
| ------------------------------------------- | ---------------------------- | ------------------------------------------ |
| `receipt` (Надходження)                     | сколько пришло, > 0          | остаток + quantity                         |
| `write_off` (Списання)                      | сколько списать, > 0         | остаток − quantity; больше остатка → `409` |
| `adjustment` (Коригування / інвентаризація) | **фактический остаток**, ≥ 0 | остаток = quantity, `delta` считает бекенд |

`quantity = 0` для `receipt`/`write_off` → `422`. Удалённый товар → `409`.

`MovementOut`: `{id, productId, type, delta, quantityAfter, reason, recordId, author: {id, name},
createdAt}`. `recordId` не пустой — списание расходников по записи (можно дать ссылку на запись).

**Импорт Excel** — первая строка заголовок, колонки по порядку:
`Назва | Артикул | Категорія | Одиниця | Об'єм упаковки | Залишок | Мін. залишок | Собівартість |
Ціна продажу | Опис`. Одиниця — `шт/мл/л/г/кг` (или `pcs/ml/…`, пусто = шт). Товар ищется по
артикулу: новый создаётся, существующий обновляется; разница остатка оформляется движением;
неизвестная категория создаётся. Строки с ошибками попадают в `errors` («Рядок 5: …») и
пропускаются — показать отчёт пользователю. Стоит дать ссылку «Завантажити шаблон» (файл можно
собрать на фронте из заголовков выше).

### Страница (по старому UI, FEATURES.md раздел 8)

- Шапка: поиск, KPI (`/inventory/summary`): Всього позицій, Закінчуються (с %), Немає в наявності
  (с %), Вартість складу.
- Фильтры: категорія, статус наявності (`stockStatus`); переключатель «Показати видалені»
  (`includeInactive`).
- Таблица: Назва / Артикул, Категорія, Залишок («N шт + остаток» и итог), Статус, Собівартість;
  действия: рух товару, редагувати, видалити.
- «Додати товар» / редактирование — `ModalForm`; для не-штучных единиц — поле об'єм упаковки.
- «Рух товару» — модалка: тип, кількість (для коригування — «фактичний залишок»), причина; рядом
  история движений товара.
- «Категорії» — список с количеством товаров, добавление, переименование, удаление с выбором
  режима (удалить вместе с товарами / перенести в «Без категорії»); системную не трогать.
- Экспорт — выбор блоков и категории; импорт — загрузка файла и отчёт.

### Расходники в записи (для Розкладу и деталей записи)

| Метод и путь                     | Тело                                                               | Ответ                                                                       |
| -------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `GET /records/{id}/consumables`  | —                                                                  | `[{movementId, productId, productName, unit, quantity, author, createdAt}]` |
| `POST /records/{id}/consumables` | `{items: [{productId, quantity}]}` (одинаковые товары суммируются) | `201` — полный список расходников записи                                    |

Мастер — только по своей записи (чужая → `404`), администратор — по любой. Нехватка товара →
`409` с текстом «Недостатньо «…»: в наявності N мл», весь запрос не применяется. По скасованій
записи → `409`. Выбор товара — `GET /inventory/products?query=` (мастеру отдаётся урезанный
список). Блок «Списання витрат» в карточке записи (FEATURES.md, решение 6).

## Звіти — `/reports`

Все эндпоинты: `dateFrom`, `dateTo` — обязательны, `dateTo > dateFrom`, период не больше двух лет
(иначе `422`). Интервал полуоткрытый `[dateFrom, dateTo)`: для «з 01.09 по 07.09» слать
`dateTo = 08.09 00:00`. Группировка — `groupBy = day | week | month` (неделя с понедельника,
по Киеву).

Как считается:

- **Виручка** — сумма неотменённых чеков по **дате чека** (не визита). Визит, оплаченный позже,
  попадает в период оплаты.
- **Середній чек** — виручка / число чеков.
- **Клієнти** (в сводке) — уникальные клиенты не отменённых записей периода; **Записи** — не
  отменённые записи периода (по дате визита).
- **Нові / повторні** (отчёт клиентов) — по завершённым визитам: новый — первый завершённый визит
  клиента в салоне попал в интервал; остальные — повторные. **Утримання** — % клиентов прошлого
  интервала, пришедших и в этом (`null` — не с чем сравнить).
- **Співробітники** — записи/завершені/не прийшли/скасовані по дате визита; виручка — чеки записей
  мастера по дате чека; рейтинг — отзывы периода.
- **Послуги** — количество в завершённых записях периода; виручка — чеки записей, сумма чека
  делится между услугами записи пропорционально их цене.

### Эндпоинты

| Метод и путь                    | Ответ                                                                                                                                                                                                                                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /reports/summary`          | `{dateFrom, dateTo, previousFrom, revenue, avgCheck, clients, records}`; каждый показатель — `{value, previous, changePercent}` за период и за предыдущий такой же длины (`[previousFrom, dateFrom)`). `changePercent = null`, если в прошлом периоде 0. Администратору `revenue` и `avgCheck` — `null` |
| `GET /reports/revenue?groupBy=` | `{groupBy, total, points: [{period, amount, receipts}]}` — точки на каждый интервал, включая пустые. Только суперюзер                                                                                                                                                                                   |
| `GET /reports/clients?groupBy=` | `{groupBy, new, returning, total, points: [{period, new, returning, total, retentionPercent}]}`                                                                                                                                                                                                         |
| `GET /reports/staff`            | `[{masterId, name, records, completed, noShow, cancelled, revenue, avgCheck, rating, reviews}]`, отсортировано по виручці; администратору `revenue`, `avgCheck` — `null`                                                                                                                                |
| `GET /reports/services`         | `{services: [{serviceId, name, category, count, revenue}], categories: [{category, count, revenue}]}`; администратору `revenue` — `null`                                                                                                                                                                |
| `GET /reports/export?groupBy=`  | `.xlsx` (`reports.xlsx`): листы Підсумки, Виручка (только суперюзер), Клієнти, Співробітники, Послуги; у администратора нет денежных колонок                                                                                                                                                            |

`period` — дата начала интервала (`YYYY-MM-DD`).

## Как проверять

- Бекенд локально по `backend/README.md`; пользователи — суперюзер, администратор, мастер.
- Склад: создать товары разных единиц, провести все типы движений, списать больше остатка
  (ошибка), удалить категорию в обоих режимах, импорт с ошибочными строками, экспорт блоками.
- Расходники: под мастером списать по своей записи и убедиться, что чужая недоступна.
- Звіти: создать и оплатить визиты за разные дни, сравнить суммы с «Фінансами»; зайти
  администратором — денежных показателей нет, графика выручки нет.
- `npm run check` зелёный; обновить `FEATURES.md` (раздел 13) и `ACCESS.md`.

## Не делать

- Не менять `backend/`.
- Несколько складов, перемещения между складами, продажу товаров через чек — бекенд этого не умеет.
