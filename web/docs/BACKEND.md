Дополняет [FEATURES.md](./FEATURES.md) и [ACCESS.md](./ACCESS.md).

Общее для всех эндпоинтов ниже:

- префикс `/api/admin/v1`, заголовок `X-Salon-Id`, ответы в конверте `{data, meta}`, поля в camelCase;
- даты и группировка по дням — в `Europe/Kyiv`;
- все изменения пишутся в журнал (`audit_log`);
- миграции шардов — backward-compatible (expand → migrate → contract).

## 1. Фильтр записей по категории услуг

`GET /records?serviceCategory=<категория>` — запись подходит, если **хотя бы одна** её услуга
относится к категории. Фильтр по `record_services` (снапшот услуг записи) через `EXISTS`.

## 2. Фильтры финансов по сотруднику и локации

| Параметр   | Где                                                                                                     | Как считается                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `masterId` | `GET /finances/operations`, `GET /finances/receipts`, `GET /finances/dashboard`, `GET /finances/export` | Мастер **записи**, к которой относится операция или чек (`record_id → records.master_id`). Операции и чеки без записи под фильтр не попадают |
| `location` | те же                                                                                                   | Локация кассы (`cash_registers.location`) через join по `cash_register_id`                                                                   |

Новый эндпоинт `GET /finances/locations` — список уникальных непустых локаций активных касс
(для выпадающего списка).

## 3. Редактирование касс

`PATCH /finances/cash-registers/{id}` — поля `name`, `location`, `isActive`.

- Баланс вручную не меняется — только операциями.
- Удаления нет, вместо него `isActive = false`. Неактивную кассу нельзя выбрать в новом способе
  оплаты и новой операции; существующие операции остаются.
- Доступ — суперюзер (как весь раздел «Фінанси»).

## 4. Абонементи — отдельная задача

Сегмент клиентов «Закінчується абонемент» требует абонементов, которых на бекенде нет. Делаем
абонементы отдельной сущностью.

### Модели (шард)

| Модель                                     | Поля                                                                                                                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SubscriptionPlan` (тип абонемента)        | `id`, `name`, `service_ids` (на какие услуги действует; пусто — на все), `visits_count`, `validity_days`, `price`, `is_active`                                                                    |
| `ClientSubscription` (проданный абонемент) | `id`, `client_id`, `plan_id`, снапшот `name`/`price`, `visits_total`, `visits_left`, `valid_from`, `valid_to`, `status` (`active` / `used` / `expired` / `cancelled`), `receipt_id`, `created_by` |
| `SubscriptionUsage`                        | `id`, `subscription_id`, `record_id`, `created_at`                                                                                                                                                |

### Эндпоинты

| Эндпоинт                                        | Назначение                                                                                                                                                                                       | Доступ                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| `GET/POST/PATCH /subscription-plans`            | Типы абонементов                                                                                                                                                                                 | администратор                              |
| `GET /clients/{id}/subscriptions`               | Абонементы клиента с остатком                                                                                                                                                                    | администратор; мастер — для своих клиентов |
| `POST /clients/{id}/subscriptions`              | Продажа: создаёт абонемент и чек на его цену                                                                                                                                                     | администратор                              |
| `POST /clients/{id}/subscriptions/{sid}/cancel` | Отмена (чек отменяется отдельно)                                                                                                                                                                 | администратор                              |
| `POST /records/{id}/payment` с `subscriptionId` | Оплата визита абонементом: `visits_left − 1`; абонемент покрывает только услуги из `service_ids` плана, остаток суммы записи доплачивается деньгами в том же запросе (`payments`), запись `paid` | администратор                              |

### Сегмент «Закінчується абонемент»

`GET /clients?segment=subscription_ending` — у клиента есть активный абонемент, у которого
`visits_left ≤ 1` **или** `valid_to` наступает в ближайшие 14 дней. Порог — константа, позже
можно вынести в настройки.

Ежедневная задача Celery переводит просроченные абонементы в `expired`.

## 5. Склад (`/inventory/*`)

### Модели (шард)

| Модель              | Поля                                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `InventoryCategory` | `id`, `name`, `is_system` (системная «Без категорії» — не удаляется и не переименовывается)                                                                                                       |
| `Product`           | `id`, `name`, `sku` (уникальный), `category_id`, `unit` (`pcs` / `ml` / `l` / `g` / `kg`), `package_volume`, `quantity`, `min_quantity`, `cost_price`, `sale_price`, `description`, `is_active`   |
| `StockMovement`     | `id`, `product_id`, `type` (`receipt` надходження / `write_off` списання / `adjustment` коригування), `delta`, `quantity_after`, `reason`, `record_id?`, `author_id`, `author_name`, `created_at` |

- Остаток хранится в единице товара (`unit`); `package_volume` — сколько единиц в упаковке. Вид
  «N шт + остаток» фронт считает по `package_volume`.
- `POST /inventory/products` принимает начальный `quantity` — он оформляется движением
  «надходження» («Початковий залишок»).
- Статус наличия вычисляется: `out` — `quantity = 0`; `low` — `quantity ≤ min_quantity`; иначе
  `in_stock`.
- Остаток не уходит в минус: списание больше остатка → `409`.
- Изменение остатка — только через движения; `PATCH` товара `quantity` не принимает.

### Эндпоинты

| Эндпоинт                                                                        | Назначение                                                                         |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `GET /inventory/products`                                                       | `query` (название или SKU), `categoryId`, `stockStatus`, `sort`, пагинация         |
| `GET/POST/PATCH/DELETE /inventory/products/{id}`                                | Карточка товара; `DELETE` — мягкое (`is_active = false`)                           |
| `GET /inventory/summary`                                                        | Всего позиций, `low`, `out`, стоимость склада (`Σ cost_price × quantity`)          |
| `POST /inventory/products/{id}/movements`                                       | Движение. Для `adjustment` передаётся фактический остаток, `delta` считает бекенд  |
| `GET /inventory/products/{id}/movements`                                        | История движений товара                                                            |
| `GET/POST/PATCH /inventory/categories`                                          | Категории (с количеством товаров)                                                  |
| `DELETE /inventory/categories/{id}?mode=delete_products\|move_to_uncategorized` | Удаление категории                                                                 |
| `POST /inventory/import`                                                        | Импорт Excel, отчёт `{created, updated, errors}` (товар ищется по SKU)             |
| `GET /inventory/export?blocks=main,stock,finance,description&categoryId=`       | Экспорт Excel                                                                      |
| `GET /records/{id}/consumables`                                                 | Списанные по записи расходники                                                     |
| `POST /records/{id}/consumables`                                                | Списание по записи: `[{productId, quantity}]` → движения `write_off` с `record_id` |

### Права

| Действие                                                                                 | Майстер            | Адміністратор | Суперюзер |
| ---------------------------------------------------------------------------------------- | ------------------ | ------------- | --------- |
| Раздел «Склад» (товары, движения, категории, импорт, экспорт)                            | ❌                 | ✅            | ✅        |
| `cost_price`, `sale_price`, стоимость склада                                             | ❌                 | ✅            | ✅        |
| Списание расходников по записи                                                           | ✅ по своей записи | ✅            | ✅        |
| Выбор товара при списании (`GET /inventory/products`, только название, единица, остаток) | ✅                 | ✅            | ✅        |

Мастеру `GET /inventory/products` отдаёт только активные товары, поля кроме названия, единицы,
остатка и статуса — `null`.

Не входит: несколько складов, перемещения между складами, продажа товаров клиенту через чек.

## 6. Звіти (`/reports/*`)

Все эндпоинты: `dateFrom`, `dateTo` (обязательны), группировка по дням — в `Europe/Kyiv`.

**Выручка = сумма оплаченных чеков** (`receipts.status ≠ cancelled`) по дате чека. Показатели по
мастерам и услугам — по чекам, привязанным к записям (`receipt.record_id`); выручка записи
распределяется по услугам пропорционально их цене в `record_services`.

| Эндпоинт                                        | Что отдаёт                                                                                                                                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /reports/summary`                          | Виручка, середній чек (виручка / число оплаченных чеков), уникальные клиенты, записи (не отменённые); по каждому — значение предыдущего периода такой же длины и изменение в % |
| `GET /reports/revenue?groupBy=day\|week\|month` | Динаміка виручки                                                                                                                                                               |
| `GET /reports/clients?groupBy=day\|week\|month` | Новые (первый завершённый визит в салоне попал в период) и повторные клиенты по периодам; удержание — % клиентов предыдущего периода, у которых был визит в текущем            |
| `GET /reports/staff`                            | По мастерам: записи, завершённые, неявки, отмены, виручка, середній чек, средний рейтинг                                                                                       |
| `GET /reports/services`                         | По услугам и категориям: количество в завершённых записях, виручка                                                                                                             |
| `GET /reports/export`                           | Все блоки в один Excel (листы по отчётам)                                                                                                                                      |

### Права

- Раздел — администратор и суперюзер, мастеру `403`.
- Денежные поля (виручка, середній чек и их динамика) — только суперюзеру. Администратору
  приходят `null`, `GET /reports/revenue` для него — `403`.

- Администратору `GET /reports/export` отдаёт файл без листа «Виручка» и денежных колонок.
- Период отчёта — не больше двух лет.

## Решения по ревью (2026-09-28)

1. Абонемент может покрывать часть услуг записи — остаток доплачивается деньгами.
2. Цены товаров и стоимость склада видит и администратор, не только суперюзер.
3. Разбивка отчётов по источникам записи не нужна.
