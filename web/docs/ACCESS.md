# Права доступа по ролям

Решение от 2026-09-23. Дополняет [FEATURES.md](./FEATURES.md).

## Роли

| Роль                                                    | Кто это                                                                      |
| ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **Майстер** (`master`)                                  | Работает только со своими записями и своими клиентами                        |
| **Адміністратор** (`administrator`)                     | Управляет салоном: всё, кроме финансов и выгрузок данных                     |
| **Суперюзер** (`administrator` + `is_superuser = true`) | Администратор с доступом к финансам, выгрузкам и управлению администраторами |

`is_superuser` — булево поле администратора. Первого суперюзера создаёт CLI `salonctl`; дальше
только суперюзер создаёт администраторов и выдаёт или снимает флаг в форме сотрудника.

Часовой пояс для всех дат и времени — `Europe/Kyiv` (фиксированный, не зависит от браузера).

## Матрица

✅ — доступно, ❌ — нет. «Свои» у мастера — записи, где он мастер, и клиенты, у которых была хотя бы
одна запись к нему.

## Допущения (проверить)

Этого в ответах не было — решил по смыслу, поправьте, если не так.

1. **Зарплаты, комиссии и статистика выручки сотрудников считаются финансами** — видит только суперюзер.
   Свой оклад в профиле видит каждый.
2. **Оплату визита проводит любой администратор**, а не только суперюзер: это работа с записью, а не раздел
   «Фінанси». Сам раздел «Фінанси» (кассы, операции, документы, дашборд) — только суперюзер.
3. **Мастер может отменить свою запись.** Если отмена должна быть только за администратором — убрать строку.
4. **Мастер не видит отзывы о себе.** Раздел «Огляд» ему закрыт целиком.
5. **Импорт клиентов из Excel** доступен любому администратору: запрет касался только выгрузки данных.

## Что нужно на бекенде

Сейчас бекенд роли не различает: `require_salon_access` проверяет только доступ к салону, мастер через API
может сделать всё то же, что администратор. Права должны проверяться на бекенде, фронт только прячет
недоступное.

| Что                               | Нужно                                                                                                                                                                             |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `is_superuser`                    | Поле у администратора (миграция), в токене и в `GET /auth/me`; в `StaffCreateIn` / `StaffPatchIn` — только для суперюзера                                                         |
| Зависимости для ролей             | `require_admin`, `require_superuser` (FastAPI `Depends`) и фильтр «только свои» для мастера                                                                                       |
| Записи                            | Мастер: `GET /records` и `/records/{id}` — только свои; создание — только с `masterId = себе`; нельзя менять `masterId`                                                           |
| Оплата отдельно от завершения     | `complete` — только нотатки и фото, ставит `paymentStatus = unpaid`; отдельный эндпоинт оплаты записи (`POST /records/{id}/payments` или чек с `recordId`) — только администратор |
| Клиенты                           | Мастер: список и карточка — только клиенты с записями к нему; `PATCH`, `DELETE`, `import` — только администратор; `export` — только суперюзер                                     |
| Сотрудники, услуги, отзывы, аудит | Только администратор; поля `salary`, `commissionPercent` и `GET /staff/{id}/stats` — только суперюзер                                                                             |
| Фінанси                           | Все `/finances/*`, включая `export` — только суперюзер                                                                                                                            |
| Уведомления (WebSocket)           | Мастеру — только события его записей; сейчас фронт отфильтровывает сам, бекенд отдаёт всё                                                                                         |
| Часовой пояс                      | Отдавать и принимать время в `Europe/Kyiv` (или UTC с явной зоной); фронт показывает всё в `Europe/Kyiv`                                                                          |

## Как это делаем на фронте

- Роль и `isSuperuser` — из `GET /auth/me` (`shared/auth`), хелперы `isMaster`, `isAdmin`, `isSuperuser`
  и `can(action)` в одном месте.
- Guard в `beforeLoad` роута: закрытый раздел → 403.
- Пункты меню фильтруются по тем же правилам.
- Кнопки и колонки, которые роли недоступны, не рендерим (а не делаем `disabled`), кроме случаев, где
  важно объяснить причину («Завершити візит» без мастера — `disabled` с подсказкой).
